# 可恢复的策略兼容性

## 零样本协作中，陌生伙伴何时值得在线适应？

**英文题目：** Recoverable Policy Compatibility: When Is Online Adaptation Worthwhile in Zero-Shot Coordination?

**项目线：** Path C（科学问题重构版）

**主领域：** JaxMARL OvercookedV2

**当前证据状态：** 固定角色开发面板中，逐格排除四个同 checkpoint 配对后，表观兼容性差距归零；对既有 403,200 条 continuation 的 64/64 真实回报读出裁决为 INCONCLUSIVE；跨训练运行机会、早期可识别性与真实切换价值均待检验。

> **中心问题：** 在排除训练身份重合之后，未见伙伴是否仍需要不同的协作模式；若需要，主体能否在有效切换窗口关闭前，从官方交互历史中选对模式并获得正的完整回报增益？

---

## 摘要

在线伙伴适应隐含了一个很少被单独检验的前提：面对不同陌生伙伴，主体确实需要采取不同策略，而且这种差异会在仍来得及改变结果时进入主体的合法观测。如果不存在可泛化的策略兼容性差距，路由器只是在已有策略之间制造方差；如果差距存在却直到不可逆决策之后才可辨，再强的历史模型也无法把它转化为回报。

本项目把这个前提变成研究对象。给定一组彼此独立、能够执行完整轨迹的协作模式，我们分别测量：未见伙伴带来的模式选择机会、当前状态与完整历史能够恢复的价值、获得预定义跨运行伙伴类型标签后的参考值，以及完整模拟器状态下的工程上限。由此可以区分三种过去常被混在一起的失败：策略库没有互补性，官方历史缺少及时证据，或真实接管抵消了选择收益。

方法在共同前缀后复制环境与伙伴状态，让每个候选模式从同一交互状态继续，并通过多次延续估计各模式的期望回报。一个小型历史路由器直接预测这些回报，而非伙伴身份或单步动作价值。部署时只使用官方历史，选择一次模式并完成余下回合。共同前缀使“选哪个模式”成为配对因果比较，也让等待、识别和接管的代价进入真实任务回报。

现有开发结果促成了这次重构，但没有证明方法机会已经存在。固定角色面板中，表观的 `119.65` 分差距在逐格删除四个同 checkpoint 配对后归零；单个 V4.4 seed-100 的 47 个触发回合也没有改变最终奖励。进一步对 225 个触发状态做 64/64 split-replica、四折 LOPO 读出后，当前注册回应通道的 oracle lift 为 `−0.0135 [−0.1649,+0.1399]`，历史读出 lift 为 `−0.3597 [−0.9326,+0.0852]`，按登记规则仍不可裁决。因此本项目首先检验一个更基础、也更有后果的问题：**跨独立训练运行的兼容性机会是否真实存在，以及它能否被及时、合法地恢复。**

## 1. 为什么这是关键科学问题

### 1.1 在线适应的三个前提

零样本协作中的性能差异可能来自伙伴惯例、任务状态、策略能力或评估构造。把所有差异都交给一个“伙伴编码器”处理，会掩盖在线适应是否有意义。一个可部署的适应器至少需要同时满足：

1. **有值得选择的策略。** 对训练来源独立的未见伙伴，不同模式的长期回报排序确实不同。
2. **证据出现得足够早。** 官方观测在模式切换仍能改变最终结果时，已经包含与价值排序有关的信息。
3. **主体能够实现选择。** 模式从共同前缀接管后仍保留优势，等待与接管不会吃掉收益。

这三个条件分别对应“机会、信息、控制”。前两项不成立时，增加模型容量或在线更新速度不会创造任务价值；第三项不成立时，离线识别准确也不会改善团队回报。

### 1.2 当前证据纠正了什么

| 观察 | 数值 | 支持的结论 |
|---|---:|---|
| 固定策略—伙伴回报跨度 | `−143.80` 至 `+168.12` | 当前策略与伙伴组合高度不稳定 |
| 表观逐伙伴 oracle 与最佳固定策略 | `139.47` 对 `19.82` | 有一个很大的库内事后上限 |
| 四个逐伙伴最优格 | `SP101→SP101`、`SP102→SP102`、`OP201→OP201`、`OP202→OP202` | 上限与 checkpoint 身份完全重合 |
| 逐格删除四个同 checkpoint 配对后的逐列最优 | `102.56, 167.88, −96.84, −94.32`，均值 `19.82` | 当前面板没有提供可泛化路由优势的正证据 |
| V4.4 seed-100 回应屏蔽实验 | 500 个匹配回合中 47 个触发；12 个回合的主体动作轨迹改变，0 个回合的奖励轨迹改变 | 当前控制器的触发没有传递为最终回报 |
| 同一冻结 checkpoint 的后续审计 | 225 个触发状态的平均动作价值排序相关为 `0.01287` | 当前分数没有可靠排序长程动作价值 |
| 64/64 split-replica、四折 LOPO 真实回报读出 | oracle `−0.0135 [−0.1649,+0.1399]`；历史 probe `−0.3597 [−0.9326,+0.0852]` | 当前触发与候选分布既无正价值证书，也无限定范围内的无机会证书；V4.4 保持冻结 |

所以，`119.65` 不是等待新模型收回的 ZSC 差距，而是一个被同 checkpoint 自匹配污染的上限。它揭示了更普遍的评估风险：只要模式库与测试伙伴共享训练身份，事后选择便可能将精确身份重合误计为“适应机会”。当前数据尚未证明历史能够读出 checkpoint 指纹。

现有四个伙伴也不足以区分“惯例”与“个体”。正式实验将为同一惯例提供多个独立训练运行，并让模式库、开发伙伴和最终测试伙伴在 checkpoint、训练运行及直接共同训练关系上分离。当前矩阵只作为 checkpoint 重合审计和任务量级参考。

证据来源：[反事实与策略矩阵报告](../../docs/status/PATH_C_V4_4_COUNTERFACTUAL_AND_LIBRARY_MATRIX_REPORT.md)、[V4.4 开发结果](../../docs/status/PATH_C_V4_4_SEED100_DEVELOPMENT_RESULTS.md)、[V4.4 真实回报读出审计](../../docs/status/PATH_C_V4_4_ARTIFACT_VALUE_READOUT_REPORT.md)。

### 1.3 研究问题与有效切换窗口

本项目检验：

> 在模式与伙伴来自独立训练运行时，伙伴惯例是否仍产生可重复的模式价值排序；这种排序能否在真实切换仍优于从头使用最佳固定策略时，由主体的官方历史恢复？

所有结论都相对于给定的共同前缀策略 `q`、模式库和接管机制。令 `J_HZ^q(t)` 表示运行 `q` 到时刻 `t` 后，同时使用合法历史与额外惯例标签并执行真实模式接管的 Bayes 期望完整回报；令 `J_fix(0)` 为从回合开始使用最佳固定模式的回报。定义

`W^q={t : J_HZ^q(t)>J_fix(0)}`

为该设置下的理论**有效切换窗口**。它表示即使把惯例直接告诉主体，切换仍有净价值的时间区间。受控有限任务可以精确计算这个窗口；生态任务以学习到的历史加惯例参考给出一个构造性窗口。实验报告整条时间曲线，而不是把事后最优时刻命名为“承诺点”。

## 2. 决策对象与可证明边界

### 2.1 从可见历史到延续价值

固定共同前缀策略 `q` 和切换时刻 `t`。记：

- `H_t`：主体按部署协议可见的完整历史；
- `S_t`：当前官方观测与任务状态摘要，且 `S_t` 是 `H_t` 的函数；
- `Z`：在确认性回报产生前，由行为契约、受控训练干预或仅使用开发伙伴的规则确定的跨运行伙伴类型；每个类型包含多个独立训练运行；
- `U_t`：可克隆模拟器中的完整当前状态，包括环境状态、伙伴策略参数与内部记忆，但不包含尚未实现的未来随机结果；
- `M={1,…,K}`：与测试伙伴训练来源分离的可执行策略模式。

从共同前缀真实接管模式 `m` 后的随机剩余回报记为 `G_t^q(m)`。其条件期望

`C_t^q(m,H_t,Z,U_t)=E[G_t^q(m)|H_t,Z,U_t,q]`

已经包含模式初始化和中途接管的后果，并对未来环境随机性取期望。由此定义：

`V_fix^q(t)=max_m E[G_t^q(m)]`,

`V_Z^q(t)=E_Z[max_m E[G_t^q(m)|Z]]`,

`V_state^q(t)=E[max_m E[G_t^q(m)|S_t]]`,

`V_hist^q(t)=E[max_m E[G_t^q(m)|H_t]]`,

`V_HZ^q(t)=E[max_m E[G_t^q(m)|H_t,Z]]`,

`V_full^q(t)=E[max_m C_t^q(m,H_t,Z,U_t)]`.

`V_fix^q(t)` 是所有共同前缀后统一接到同一模式的最佳值，与“从回合开始的最佳固定模式”不同。`V_Z` 只允许按预先定义的伙伴类型选择模式；`V_state`、`V_hist`、`V_HZ` 和 `V_full` 则依次允许使用当前状态、完整合法历史、历史加类型标签以及完整当前状态。信息包含关系给出两条序列：

`V_fix^q ≤ V_state^q ≤ V_hist^q ≤ V_HZ^q ≤ V_full^q`,

`V_fix^q ≤ V_Z^q ≤ V_HZ^q ≤ V_full^q`.

`V_Z` 与 `V_state、V_hist` 一般没有固定顺序。令

`Γ_compat^q(t)=V_Z^q(t)−V_fix^q(t)`

表示在平衡任务条件并平均类型内部差异后，不同跨运行伙伴类型是否需要不同模式。这是 H1 的主要对象，不会把普通状态路由价值算成伙伴兼容性。

`V_Z` 是总体机会，并不自动证明类型—模式关系能迁移到新训练运行。令开发伙伴上冻结的映射为

`m^dev(z)=min argmax_m E_dev[G_t^q(m)|Z=z]`,

并在确认性伙伴上定义

`V_transfer^q(t)=E_test[G_t^q(m^dev(Z))]`,

`V_fix,test^q(t)=max_m E_test[G_t^q(m)]`.

`V_transfer−V_fix,test` 测量同一类型的模式选择能否跨训练运行复用。H1 同时要求总体机会存在，并且这项前瞻迁移值具有实际意义。

这些差值回答不同问题：

- `Γ_state^q=V_state^q−V_fix^q`：即时任务状态及其留下的伙伴痕迹所支持的路由价值；
- `Γ_mem^q=V_hist^q−V_state^q`：时序历史相对当前状态的增量价值；
- `Γ_hist^q=V_hist^q−V_fix^q`：所有官方历史可支持的最大路由价值；
- `Γ_unseen^q=V_HZ^q−V_hist^q`：知道跨运行伙伴类型后仍能消除、但官方历史尚未消除的歧义；
- `V_full^q−V_HZ^q`：类型标签之外的个体参数、内部记忆与隐藏任务状态所提供的工程上限。

`Γ_hist` 可能同时包含任务状态与伙伴行为信息；二者通过 `state-only` 对照、跨类型的合法轨迹干预和跨运行泛化来区分。伙伴行为流置换只作为模型敏感性分析，不承担因果解释。

`Z` 的成员资格不使用确认性伙伴的模式价值向量。同类型训练运行能否形成一致的模式排序、不同类型能否形成可分离排序，都是实验结果。若这种结构没有在 held-out runs 上出现，`Z` 只被称为“跨运行伙伴类型”，不被解释为协作惯例。

### 2.2 历史路由器的紧上界与端到端收益

对任意只读取官方历史的路由器 `g:H_t→M`，

`E[G_t^q(g(H_t))] ≤ V_hist^q(t)`.

逐历史选择条件期望最高的模式达到等号，因此该界在给定模式库与观测协议下是紧的。学习路由器 `ĝ` 的预测遗憾为

`R_pred^q(t)=V_hist^q(t)−E[G_t^q(ĝ(H_t))]`.

令 `B_t^q` 为共同前缀的期望累计回报，并定义

`J_sfix^q(t)=B_t^q+V_fix^q(t)`,

`J_route^q(t)=B_t^q+E[G_t^q(ĝ(H_t))]`.

在匹配前缀比较中有精确等式

`J_route^q(t)−J_sfix^q(t)=Γ_hist^q(t)−R_pred^q(t)`.

再令

`C_wait^q(t)=J_fix(0)−J_sfix^q(t)`.

`C_wait` 是有符号差值：共同前缀可能损失回报，也可能优于从头固定模式。端到端增益满足

`J_route^q(t)−J_fix(0)=Γ_hist^q(t)−R_pred^q(t)−C_wait^q(t)`.

真实接管已经包含在 `G_t^q` 中，因而无需再扣一次“切换成本”。在 OvercookedV2 中，学习路由器只能给 `V_hist` 提供构造性下界：显著优于 `J_sfix` 可以证明存在可恢复价值，未能优于则只说明当前注册模型没有找到它。受控有限任务将用于计算精确 Bayes 值。

### 2.3 最坏情况下的匹配上下界

考虑一个静态二惯例特例：两种惯例等先验，由同一个固定 `q` 产生历史分布 `P_0^t,P_1^t`；两种模式各自只与一种惯例匹配；选对和选错的剩余回报分别为常数 `r+` 与 `r−`，`Δ=r+−r−>0`。采用

`TV(P,Q)=½||P−Q||_1`.

二元 Bayes 检验的最小错误率为 `(1−TV)/2`，所以

`V_HZ^q(t)−V_hist^q(t)=Δ(1−TV(P_0^t,P_1^t))/2`,

`V_hist^q(t)−V_fix^q(t)=Δ·TV(P_0^t,P_1^t)/2`.

第一式是任何历史方法的不可避免遗憾，第二式由 Bayes 路由器达到；两者给出匹配上下界。`Δ` 决定错误模式的任务代价，`TV` 决定合法历史中有多少选择价值可以恢复。

若历史中唯一随惯例变化的证据是 `n` 个独立 Bernoulli 回应，参数分别为 `(1−κ)/2` 与 `(1+κ)/2`，其中 `0<κ≤1/2`，希望相对惯例参考的遗憾不超过 `ε≤Δ/8`，则任何方法都需要

`n ≥ log(Δ/(4ε))/(4κ²)`,

而经验均值阈值检验在

`n ≥ 2log(Δ/ε)/κ²`

时已经足够。下界来自二点检验与单步 `KL≤4κ²`，上界来自 Hoeffding 集中，因此最坏情况下的历史需求精确到常数阶为

`Θ(log(Δ/ε)/κ²)`.

这个特例不替代一般序列任务；它证明一个不可绕过的事实：当伙伴证据太弱，以至于所需历史长于有效切换窗口时，模型复杂度无法补回丢失的回报。

## 3. 假设与预期贡献

### 3.1 三个顺序假设

- **H1，跨训练运行的兼容性机会。** 在模式库与测试伙伴训练来源分离时，预定义伙伴类型仍对应可重复的模式价值排序：总体 `Γ_compat^q(t)>0`，且开发伙伴上冻结的类型—模式映射在完全留出的伙伴上产生有实际意义的 `V_transfer^q(t)−V_fix,test^q(t)>0`。
- **H2，有效窗口内的构造性可识别价值。** 在已实现切换窗口内，只读取官方历史的路由器优于统一后接模式；状态和合法伙伴干预对照用于区分即时状态、时序记忆与伙伴类型效应。
- **H3，端到端的伙伴条件控制价值。** 在完全留出的伙伴上，一次真实模式切换提高完整回报，其选择方向与独立延续价值排序一致，且收益随跨运行伙伴类型系统变化。若收益完全由任务状态解释，结论收缩为状态条件策略路由。

中心主张要求 H1–H3 联合成立。H1 是方法开发的科学入口，H2 给 `Γ_hist` 一个可执行下界，H3 检验这一下界在扣除等待与真实接管后是否仍为伙伴条件的正收益。

### 3.2 预期贡献

1. **揭示并修正身份重合造成的表观适应机会。** 将 exact-checkpoint oracle、伙伴个体差异和跨训练运行的惯例兼容性分开估计。
2. **把信息价值分解操作化为 ZSC 诊断。** 在同一模式库下同时报告状态、历史、惯例和完整状态参考，从而定位机会、信息与控制瓶颈。
3. **用共同前缀的真实延续价值训练路由。** 每个监督标签都回答“此刻接到该模式会得到什么”，并通过前瞻切换直接接受任务回报检验。
4. **给出时间上的可能性边界。** 经验切换窗口与二惯例匹配界共同说明：在线适应何时有价值、何时因信息来得太晚而原则上无效。

## 4. 反事实价值路由

### 4.1 独立的模式库与伙伴面板

模式是能够独立执行完整轨迹的 actor policy，而非共享 actor 的多个 critic 头。每一种候选惯例由多个独立训练运行实例化，数据分成三层：

- **模式库：** 提供可执行候选策略；
- **开发伙伴：** 用于模式筛选、共同前缀策略与切换时刻选择；
- **确认性伙伴：** 只用于最终泛化评估。

三层之间不共享 checkpoint 或训练运行。`Z` 由预先指定的行为契约、受控训练目标或只使用开发伙伴的规则给出；Self-Play、Other-Play 等算法名称本身只是来源标签。确认性伙伴的类型归属不读取其模式价值。模式保留依据是开发伙伴上的非支配价值剖面，而同类型跨独立运行是否产生稳定排序则由最终实验检验。

### 4.2 同一前缀的多模式延续

共同前缀策略 `q` 运行到候选时刻后，训练环境复制当前物理状态、伙伴策略参数与循环状态。候选模式通过重放官方历史初始化内部记忆，再从同一快照分别接管。未来随机流从快照后重新抽样，并在模式间配对；模式选择与最终价值评价使用分离数据，避免把选择噪声计入参考收益。每个前缀—模式组合以多次独立延续估计期望回报。

这项测量需要可克隆的训练模拟器。部署路由器仍只接收官方历史；模拟器隐藏状态只用于训练标签和参考上限。若环境或伙伴内部状态无法复制，本研究的成对反事实诊断不直接适用。

### 4.3 价值模型与一次切换

序列模型 `s_φ(H_t,m)` 输出每个模式的期望延续回报。训练使用回报回归和价值加权排序，部署选择

`ĝ(H_t)=argmax_m s_φ(H_t,m)`.

输入在表示层区分任务与主体轨迹、伙伴行为轨迹和当前官方状态，以支持来源分析。评价以所选模式在独立未来延续中的回报为准，伙伴分类准确率仅作为解释性读数。

第一阶段在预先选择的时刻只切换一次，并保持所选模式至回合结束。`q` 被视为实验干预：不同 `q` 可能改变伙伴暴露的信息、到达的任务状态和剩余兼容性机会。主实验先固定 `q`；比较 scout 的价值属于后续独立问题。

## 5. 实验设计

### 5.1 现有数据：checkpoint 重合审计

现有固定角色 5×4 面板用于重现两项事实：表观 `119.65` 分差距是否完全由四个同 checkpoint 格承载，以及逐格删除这些配对后是否仍有正差距。这个删除操作不是全局 run-disjoint 设计；五个主体中的四个仍分别出现在伙伴集合中。选用单一现有策略生成的四伙伴轨迹，还可检查早期历史是否对 checkpoint 身份敏感。由于只有四个伙伴级单位，且标签来自不同整回合状态分布，这项分析不估计 `Γ_hist`，也不作为正式 H1 检验。

同一批 V4.4 产物还完成了一项更窄的回应通道审计：对每个触发状态的 128 个 replica 固定拆成 64 个拟合与 64 个评价样本，以三个伙伴拟合、第四个伙伴评价，并在 10,000 次伙伴分层 bootstrap 中重做整条读出流程。该审计的主裁决为 INCONCLUSIVE：oracle 与历史读出的 LCB95/UCB95 都跨越 0。未决具体来自固定伙伴触发状态少且不均衡、伙伴异质性和从三个伙伴外推到第四个伙伴的证据不足。它说明当前注册回应、当前六动作候选与当前触发分布尚未给出可执行的价值结论；它不测量跨运行模式兼容性，也不把 `119.65` 恢复为机会证据。V4.4 因此继续冻结，proposal 的阶段 A 不以新增 RL 为起点。

### 5.2 阶段 A：建立 held-out 兼容性机会

在 Test Time Simple 中扩展为嵌套面板：每种预定义伙伴类型包含多个独立模式运行和多个独立伙伴运行，模式侧与伙伴侧完全分离。先以平衡任务 seed 的完整回合矩阵估计 `V_Z−V_fix`，再在共同前缀上测量状态、历史与历史加类型参考。

主要比较是：

- 最佳伙伴无关模式；
- 知道惯例但面对该惯例新 checkpoint 的模式选择；
- 知道精确伙伴运行后的事后参考；
- 含同 checkpoint 自匹配的旧式 oracle。

四者的差异分别显示可泛化类型机会、个体特异机会和 checkpoint 重合带来的上限膨胀。模式选择使用一组回合或未来延续，回报估计使用另一组独立数据。H1 的统计单位是训练运行，而非单个 episode；其最小实际意义阈值 `δ_min` 以一次正确交付的原始回报为尺度，并在确认性面板生成前确定。

其中 `V_Z` 作为 held-out 面板上的总体机会参考单独报告。跨运行主读数使用开发伙伴冻结 `m^dev(z)` 及其并列选择规则，再原封不动地评价确认性伙伴；训练运行级 leave-one-run-out 嵌套交叉拟合作为重复验证。确认性伙伴的回报既不参与类型—模式映射，也不参与模式保留。

### 5.3 阶段 B：受控可恢复性相图

有限合作任务独立操纵四个可观察因素：错误模式的价值损失 `Δ`、伙伴证据强度 `κ`、证据出现时间和不可逆任务事件。环境的 Bayes 路由值可精确枚举，因此能够同时验证：

- `V_fix≤V_state≤V_hist≤V_HZ≤V_full` 及 `V_fix≤V_Z≤V_HZ`；
- 二惯例的 TV 精确式；
- `Θ(log(Δ/ε)/κ²)` 的必要与充分历史长度；
- 当证据晚于有效切换窗口时，oracle 有机会而历史路由无净收益。

这一步给理论对象建立可计算阳性与阴性对照，不用生态任务中的学习器失败代替信息论结论。

### 5.4 阶段 C：OvercookedV2 共同前缀实验

每个候选时刻比较六类控制：

| 控制 | 对应的理论对象 |
|---|---|
| 从回合开始的最佳固定模式 | `J_fix(0)` |
| 共同前缀后统一接到最佳模式 | `J_sfix^q(t)` 与等待差值 |
| `state-only` 路由 | `V_state` 的构造性下界 |
| 完整历史路由 | `V_hist` 的构造性下界 |
| 历史加类型参考 | `V_HZ` 的构造性下界与已实现切换窗口 |
| 完整模拟器状态参考 | `V_full` 的构造性下界 |

伙伴身份分类、ReCoLLAB 式类型路由、端到端历史适应器和策略库组合方法作为方法基线。伙伴条件效应的主要证据来自相同任务 seed 下随机改变预定义伙伴类型并重新运行完整合法轨迹，以及路由器向同类型新 checkpoint 的泛化。伙伴历史置换只检验模型对输入流的敏感性，因为置换后的历史未必符合环境动力学。

主终点是未见伙伴上的完整回合原始团队回报。匹配前缀的路由增益

`J_route^q(t)−J_sfix^q(t)`

定位选择价值；相对从头固定模式的

`J_route^q(t)−J_fix(0)`

检验部署净收益。在生态任务中，记学习到的历史加类型参考为 `Ĵ_HZ^q(t)`；它是理论

`J_HZ^q(t)=B_t^q+V_HZ^q(t)`

的构造性下界。由此得到的

`Ŵ^q={t:Ĵ_HZ^q(t)>J_fix(0)}`

是理论有效窗口的构造性子集。当总体均值上的已实现类型参考差值明确为正时，报告相对该参考的回收率

`ρ̂(t)=[J_route^q(t)−J_sfix^q(t)]/[Ĵ_HZ^q(t)−J_sfix^q(t)]`.

该比率只表示相对已实现参考的回收程度，不等同于理论 `V_HZ` 的精确回收率。它采用总体均值差之比，并与分子、分母区间同时报告；原始回报差始终是主要结果。有限延续选出的完整状态参考同样只是 `V_full` 的构造性下界。

### 5.5 泛化与统计推断

伙伴运行与模式库训练运行形成双向交叉依赖。统计推断在两侧按训练节点重采样，或使用相应的交叉层级模型；同一配对的重复回合只提高该配对均值的精度。若实验只有一套模式库，结论明确条件于该库；一般方法主张需要多个独立模式库和路由器训练实例。

最终测试伙伴遵守 §4.1 的三层数据分离，并仅用于泛化评价。Test Time Wide 用于检验空间冲突和更长路径是否改变有效窗口。只有 H1–H3 在 OvercookedV2 中闭合后，Hanabi 才作为信息结构不同的条件性复现领域。

## 6. 与现有工作的关系

训练多样性与评估工作已经把兼容性放在中心位置。[BRDiv](https://openreview.net/forum?id=l5BzfQhROl) 以 best-response compatibility 生成训练伙伴；[ZSC-Eval](https://papers.nips.cc/paper_files/paper/2024/hash/54a7139c548c88e288aa0fcd2bcbeceb-Abstract-Datasets_and_Benchmarks_Track.html) 用近似 best response 的行为多样性筛选评估伙伴，并以 BR-Prox 衡量 ego 相对近似 best response 的性能。本项目把统计对象进一步放到同一局、同一物理前缀后的剩余模式价值。

伙伴推断与策略选择已有清晰先例：[PLASTIC-Policy](https://ojs.aaai.org/index.php/AAAI/article/download/9428/9287)、[Strategy Matching](https://arxiv.org/abs/2210.15099)、[PECAN](https://arxiv.org/abs/2301.06387)、[Theory of Mind Guided Strategy Adaptation](https://doi.org/10.65109/UMCV8852) 和 [TALENTS](https://proceedings.neurips.cc/paper_files/paper/2025/hash/020973f2093a6053261da93cac30ab71-Abstract-Conference.html) 都利用历史、伙伴模型或潜在策略选择协作行为。[Partner Modelling Emerges in Recurrent Agents](https://openreview.net/forum?id=WydxWM2xNb) 进一步表明，只有伙伴特定适应会改善任务表现时，结构化伙伴表征才会出现，并考察了单局伙伴切换。[GPAT](https://arxiv.org/abs/2510.16187) 通过策略库组合适应伙伴，[CooT](https://arxiv.org/abs/2506.23549) 则从交互上下文直接生成互补动作。

与本方案控制协议最接近的是 [ReCoLLAB](https://arxiv.org/abs/2512.22129)：它在 early probe window 中识别伙伴类型，随后一次路由到对应 best response。本项目在同一前缀对全部模式做配对延续，估计 time-indexed 的 `V_fix/V_Z/V_state/V_hist/V_HZ/V_full`，并用 checkpoint-disjoint 面板检验类型标签与合法历史各自能够恢复多少策略库价值。

[PACE](https://proceedings.mlr.press/v235/ma24n.html) 优化伙伴识别导向的探索；[ConventionPlay](https://openreview.net/forum?id=X1EnygvhoZ) 已把 convention 表述为策略空间中组内兼容、组间不兼容的类别，并通过能力受限种群诱导 repertoire probing 与 convention steering。本项目先测量被动合法历史的 time-indexed recoverability；主动探查只在被动信息不足且干预后的净任务价值为正时进入下一阶段。

标准决策信息价值提供了本方案的 Bayes 视角，相关工作包括 [Arumugam 与 Van Roy](https://papers.nips.cc/paper_files/paper/2021/hash/517da335fd0ec2f4a25ea139d5494163-Abstract.html)；[Information before Commitment](https://arxiv.org/abs/2607.16895) 则在统一安全约束的自适应控制中形式化了 precommitment information。现有工作已经覆盖兼容性类别、短前缀类型识别、策略切换、主动探查和承诺前信息。本项目聚焦一个更窄的测量问题：在训练身份完全分离的同前缀比较中，跨运行类型与合法历史分别能够恢复多少策略库价值，以及这部分价值能否通过真实接管改善单局回报。

## 7. 结果的科学解释

| 结果 | 科学结论 |
|---|---|
| 全局 run-disjoint 面板上 `V_Z≈V_fix` | 当前模式库中未观察到可泛化的伙伴类型路由机会；旧 oracle gap 与 checkpoint 重合一致 |
| `V_Z>V_fix`，但 `V_transfer≈V_fix,test` | 面板内存在类型条件的事后机会，但类型—模式关系没有跨训练运行复现 |
| `V_Z>V_fix`，但已实现窗口内历史路由不优于统一后接模式 | 伙伴类型机会存在，但当前注册模型尚未给出历史可恢复价值的构造性证据 |
| `state-only` 已达到历史路由 | 模式选择可由即时状态完成，额外时序记忆不是主要来源 |
| 完整历史优于 `state-only`，且跨类型合法干预按预测改变排序 | 支持伙伴的时序行为为模式选择提供可执行信息 |
| 匹配前缀收益为正，端到端收益不为正 | 选择本身有效，但共同前缀的等待代价抵消了部署收益 |
| 开发伙伴有效、独立 checkpoint 无效 | 结果与个体指纹或开发分布拟合一致，尚不支持可迁移兼容性 |
| 独立伙伴上端到端收益为正，且干预排序一致 | 支持“及时的兼容性证据经真实模式切换产生回报”的因果链 |
| 既有注册回应通道的 oracle 与 LOPO readout 区间均跨 0 | 当前 V4.4 触发/候选分布不可裁决；不启动新 RL，也不据此否定其他主动探查机制 |

这些结果模式用于区分跨运行机会、合法信息、时机和控制实现；证据不足时，相应环节记为不可裁决。

## 8. 影响与适用范围

该研究首先是一项在线适应的**可行性诊断**，其次才是一种路由方法。它要求训练阶段能够复制环境与伙伴状态，以生成同前缀的多模式延续；这一条件适合模拟基准，不直接覆盖真人伙伴或不可克隆系统。部署阶段不使用伙伴标签、隐藏状态或未来分支，只读取官方历史。

若 H1 成立，将支持当前模式库与评估分布中存在跨训练运行可重复的策略兼容性机会；若 H2 成立，将得到其中可由合法历史恢复的构造性下界；若 H3 进一步成立，才说明反事实价值路由能够把这部分信息转化为真实团队回报。若某一环节未获支持，结论收缩到相应的可行性边界，并结合受控上界区分任务本身的限制与当前实现的限制。

本项目最终检验的命题是：**跨运行的兼容性机会与及时可见的信息是否共同设定零样本伙伴适应的可实现上限，以及一次真实策略切换能否在该上限内取得正净收益。**
