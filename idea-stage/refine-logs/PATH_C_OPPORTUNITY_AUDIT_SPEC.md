## 0. 审计角色与准确范围

R015 是当前项目优先执行的决策支持实验，原因是前身基底两次出现“伙伴回应可由瞬时公共状态解释”的退化，且本基底唯一一次旧控制器运行没有执行任何探查。R015 用一次较便宜的测量判断正式顺序分支方法是否值得进入大规模训练。R015 审计控制器现已作为独立静态模块实现；伙伴条件折扣原始回报头和有限原型两步代理量仍只是学习路径中的诊断实现，不能替代该审计控制器，也不能解除 1000 万步学习版正式控制器的未实现保护。静态代码与软件核查均不构成 R015 读数。

这是一项当前资源排序，不是新增的通用启动条件。已经花掉的计算无法追回，不等于失败在运行后无法识别或修复；因此 R015 不改变 `OPERATING_CONSTRAINTS.md` §7.2 的启动条件规则。

R015 的正结果证明冻结支持上存在一个官方观测可实现的单次探查控制器。R015 的普通负结果只否定该注册控制器，不能终止整个 OvercookedV2 基底。只有经独立证明的完整信息上界低于实际意义门槛时，才允许作基底范围内的保守否定。

Hanabi 是投稿级主张所需的第二领域。held-out 伙伴族评估也属于后续论文范围；它与 R015 的支持内伙伴池严格分开，不能由 R015 代替。

独立设计数据只选择过滤器近似数值和规划分支数。旧版过滤器的 80 条历史已经参与形成
2026-07-18 修订，不能再次充当修订后过滤器的选择数据。新版协议必须另取与旧设计历史、评估
seed 8115 一系、试点和正式数据都不相交的 80 条回合随机数；伙伴准入矩阵的跨 seed 回报只是
支持成立的背景事实，不能进入任何选择统计。候选网格、统计量、门槛、百分位算法和优先次序
保持不变，并在新设计数据前再次绑定；设计数据只回答哪个候选首先通过，不能在看过结果后
扩网格或改门槛。

试点 80 个配对块只输出接线核查、配对差的描述性离散程度、规划分叉环境步数、吞吐和零探查
解释计数。试点均值、符号和方差不参与正式轮数或效应判定，试点数据永不进入正式统计。

## 1. 研究对象与保证

### 1.1 主体可见历史、完整隐藏状态和后验

令 `h_t^ego` 表示主体智能体在时刻 `t` 按官方协议可获得的全部历史。以下字段表是 R015 专用主体可见历史合同；机器预登记用 `ego_evidence_contract` 制品键绑定它，其他文件只引用本节，不另增字段。旧代码类 `EgoEvidenceSpecV1` 含评估器记录的伙伴原始动作，只能服务历史机制仪器，不是本合同：

- 官方局部观测；
- 主体自身过去的动作；
- 主体自己选择的 option 或候选脚本及其已持续时长；
- 原始团队回报和回合边界；
- 只能由前述字段确定导出的合法动作掩码、任务进展和 `ResponseSummarySpecV1` 回应记号。

本审计在任何设计数据产生前把 `ResponseSummarySpecV1` 具体绑定为现有
`REGISTERED_LOCAL_RESPONSE_SPEC`：回应类别依次为 `visible`、`unseen` 和
`local_non_agent_change`，延迟上界只有 1 步。记号只比较相邻两次官方局部观测；先判断主体
周围可见的非智能体层是否变化，再判断伙伴是否可见，不能读取评估器记录的伙伴动作。该定义
的内容摘要在机械冻结时从同一实现重算，设计数据和试点不得换用主 Path C 的十类回应定义。

主体 option、脚本和时长是主体可控的内部记录，不增加环境信息。伙伴原始动作只有在上述官方历史可以唯一恢复时才能作为派生字段；此时必须同时保存恢复函数和语义哈希。直接读取评估器记录的伙伴动作属于 action-augmented 信息增强诊断。伙伴身份、伙伴私有观测、伙伴循环网络隐藏状态、完整网格、不可见配方、评估器随机数状态和任何训练族标签都不属于 `h_t^ego`。

令 `U_t` 表示所有不属于 `h_t^ego`、但会影响后续回报的状态，至少包括伙伴原型 `theta`、伙伴内部记忆、伙伴私有观测、隐藏环境变量和持续性外生状态。审计中的正确信息状态是

`nu_t(du) = P(U_t in du | h_t^ego)`。

给定评估器完整轨迹后可以重放某个伙伴网络，不意味着给定 `h_t^ego` 后 `U_t` 退化为 `theta`。R015 的任何正式动作都必须是 `h_t^ego` 的函数；完整状态只能用于产生模拟数据、核对实现或构造保守上界。

### 1.2 三个正式实验组和一个诊断组

R015 把探查预算冻结为每回合最多一次。单次探查是后续多次探查方法允许的一个子类：正结果足以证明机会存在，负结果不排除更复杂的多次探查策略。

- **回应屏蔽参照组 `A1`：** 使用冻结的官方观测信念过滤器、完整候选脚本集和相同规划器；它可以选择具有普通任务价值的脚本，但脚本触发的注册回应记号不进入专用伙伴信念更新支路。这样，`A1` 不是一个人为削弱的“只能原地做事”基线，而是按冻结规划器选出的回应屏蔽参照。
- **执行探查但屏蔽回应组 `A2-mask`：** 在冻结规则首次选择探查脚本 `p` 时执行它；脚本结束后保留主体可见的任务转移 `x`，但不把该脚本触发的注册回应记号 `y` 送入专用伙伴信念更新支路。
- **执行探查并使用回应组 `A2-use`：** 与 `A2-mask` 在探查前使用相同历史、候选、脚本和随机数；脚本结束后允许 `y` 进入专用伙伴信念更新支路。两组此后都不再探查。
- **原始骨干组 `A0`：** `pi_base` 原样运行，只诊断咨询层是否自伤，不进入正式机会判定。

`A1`、`A2-mask` 和 `A2-use` 在候选探查发生前必须保留完全相同的被动官方历史和被动信念更新；屏蔽只作用于当前候选脚本归属的注册回应记号。原始官方局部观测始终保留，因此该对照识别的是**显式注册回应通道的增量使用效应**，不是从历史中删除全部伙伴行为证据后的总信息效应。具体字段投影和接口可见性在 §2.3 冻结，不能只靠“调用时忽略”实现。

旧版“告知伙伴身份组”可保留为完整状态诊断，但不进入正式实验组，也不承担上界作用。

### 1.3 不变分解：注册回应通道收益、探查成本和净收益

记完整回合原始回报为 `V(A)`。定义

`Delta_response = E[V(A2-use) - V(A2-mask)]`，

`Delta_cost = E[V(A1) - V(A2-mask)]`，

`Delta_net = E[V(A2-use) - V(A1)]`。

由同一批回报的代数关系，恒有

`Delta_net = Delta_response - Delta_cost`。

这是 R015 的核心研究对象。`Delta_response` 回答显式注册回应通道是否增量改变后续控制；它不等于全部伙伴信息的价值。`Delta_cost` 回答选择该探查脚本而不是最佳回应屏蔽动作付出了多少任务机会；`Delta_net` 回答启用该通道后是否仍得到净收益。普通任务进展不能再被误记成回应通道价值，因为 `A1` 也能选择任务价值最高的候选，且同一个探查脚本的任务进展同时存在于 `A2-use` 与 `A2-mask` 中。

三个期望都条件于主体固定在 `agent_1` 厨师席、伙伴固定在 `agent_0` 信号席；因此本文所称
净收益均为厨师席净收益，不再混合两个物理上不可交换的角色。

### 1.4 可实现性与学习器非主张

`A2-use` 的所有动作只依赖 `h_t^ego`，所以它是信息意义上可实现的显式控制器。它可以使用精确枚举、粒子过滤或其他冻结算法；近似误差是该控制器的一部分，最终由实际回报承担。

2026-07-18 的过滤器修订发生在试点和正式数据之前，但它会改变 `q_t`、延续成员路由和是否
探查，因此会改变三个正式实验组的具体已执行策略。§1.3 的配对差定义、代数恒等式和 §3--§4
的统计合同不变；正式期望从此明确指向修订后注册控制器，不能声称旧版过滤器会产生相同轨迹
或相同数值估计对象。旧设计数据从未进入正式统计。

R015 不声称命题二中的单步 `4 epsilon + 4 B rho` 界能控制整局学习器误差。该界要求固定且正确的当前信念和精确成本，不覆盖累计过滤误差、规划截断误差或重复模型误差。R015 正结果只证明“一个官方观测控制器取得了该收益”；神经学习器能否逼近它由后续匹配训练实验回答。

### 1.5 完整信息保守上界

令 `Pi_obs` 为满足冻结动作、窗口、预算和安全规则，且动作只依赖 `h_t^ego` 的目标控制器类别。令 `Pi_full` 使用相同动作和约束，但还可观察完整 `U_t`，并满足 `Pi_obs` 包含于 `Pi_full`。定义

`Delta_class_star = sup_{pi in Pi_obs} E[V(pi)] - E[V(A1)]`，

`V_full_star = sup_{pi in Pi_full} E[V(pi)]`。

因为 `A2-use` 属于 `Pi_obs`，且 `Pi_obs` 包含于 `Pi_full`，所以

`Delta_net <= Delta_class_star <= V_full_star - E[V(A1)]`。

因此，只有一个经过证明的数值上界 `V_full_upper >= V_full_star` 才能产生保守终止量

`Delta_upper = V_full_upper - E[V(A1)]`，

从而得到正确的夹逼关系

`Delta_net <= Delta_class_star <= Delta_upper`。

证明只使用两件事：目标控制器属于更小的信息和策略集合；`V_full_upper` 确实不低于更大集合的最优值。告知伙伴身份但仍采用固定短视规划、有限前瞻或有限蒙特卡洛的控制器不满足第二件事，不能代替 `V_full_upper`。

当前项目尚无经过证明的 `V_full_upper` 实现。R015 可以在没有它时确立机会或否定注册控制器，但不得据此宣称“该基底没有任何可利用机会”。

### 1.6 实际意义门槛

冻结规则为

`m = 0.25 * R_delivery`，

其中 `R_delivery` 在运行授权时从绑定的环境源代码回读。若正确交付原始回报为 20，则 `m=5`。`m` 表示项目愿意为后续大规模训练投入资源所要求的最低每局净回报，不使用外部论文的标准差为它提供统计含义。

脚本长度、窗口、过滤器、规划精度、安全阈值和样本量同样会改变结论；它们都是正式科学选择，不再把 `m` 的系数称为唯一实质判断。

## 2. 控制器构造

### 2.1 官方观测过滤器

冻结过滤器记为

`q_t(U) = F(h_t^ego)`。

过滤器不得读取评估器完整状态。若使用精确模式，必须对完整 `U=(theta, execution_state)` 枚举或独立抽样，并通过归一化、重构和小规模差分核对；若使用近似模式，粒子数、重采样规则和随机数坐标在设计数据上冻结。无论哪一种模式，正式动作只读取 `q_t` 和 `h_t^ego`。

旧版 `stratified_hidden_state_particles_v1` 从无条件开局先验产生固定数量提议，并让每个粒子每步
只抽一个伙伴动作后作零或一的硬拒绝。独立 80 条设计历史上的六个候选均以零支持关闭率 1.0
失败；有效样本量比例随粒子数增加仍约为 0.05。特权重放证明真实轨迹在绑定模型下保持相容，
因此扩大同一网格不能修复单动作拒绝造成的路径耗尽。旧选择报告继续绑定为
`filter_design_precision_infeasible` 的触发记录，不得改写、合并或进入新版选择。

修订后的近似过滤器标识为 `official_history_fully_adapted_particle_filter_v2`。这里“完全适应”
表示提议在每一步先条件于刚观察到的官方历史，再抽取相容后继；它不表示有限粒子近似等于精确
后验。四个原型先验仍各为 0.25。开局对每个原型从登记先验独立产生提议，并只把与开局官方
局部观测相容的提议计为粒子，直到得到恰好 `P` 个条件化开局粒子。被拒绝的原始提议只计入
计算成本，不占粒子槽；禁止复制少数接受样本补满 `P`，每个接受槽必须保留自己的提议随机键
和状态摘要。开局提议键仍不得读取实际伙伴身份、真实 episode seed 或完整真实状态。

逐步更新时，属于原型 `k` 的父粒子 `i` 只调用一次该原型的伙伴网络，由一次前向得到六个官方
动作的概率 `pi_k(a|z_i)`。令 `c_i(a,xi)` 表示从该父状态执行动作 `a` 和环境随机结果 `xi`
后，主体下一官方局部观测、原始团队回报和回合边界均与记录相同。对动作和登记环境转移中会
影响该匹配的随机结果作精确边缘化：

`L_i = sum_{a,xi} pi_k(a|z_i) * p(xi|z_i,a) * c_i(a,xi)`。

父粒子的重采样前权重为

`w_bar_i = w_i*L_i / sum_j(w_j*L_j)`。

若 `L_i>0`，从与观察相容的条件分布

`P(a,xi|i,h_{t+1}^ego) = pi_k(a|z_i)*p(xi|z_i,a)*c_i(a,xi)/L_i`

抽取唯一后继；不得重新退化为先抽一个动作或一个环境结果再硬拒绝。伙伴循环状态不以抽中的
动作作为输入，所以六个动作共享同一次网络前向产生的下一循环状态。

有效样本量（effective sample size，ESS）固定在重采样前按 `1/sum_i(w_bar_i^2)` 计算，第三项
过滤门（S3）的
分母始终是该原型登记的 `P` 个父粒子槽。动作分支数、四原型总槽数、开局被接受的提议数和
重采样后复制数都不得改变分母。重采样复制必须保留共同祖先记录；ESS 只衡量权重集中，不能
冒充隐藏状态多样性。只有某原型的有限父粒子云满足 `sum_i(w_i*L_i)=0` 时才记录
`finite_particle_cloud_zero_support`。这表示当前有限近似没有相容后继，不表示该原型模型对完整
历史赋零概率；仍按整块失效规则关闭且不得回退到真实隐藏状态。

粒子数候选仍为 `{64,128,256}`；重采样时机仍为“逐原型 ESS 小于 `0.5P` 时自适应触发”和
“每环境步触发”。逐原型系统重采样采用同一相位的 `P` 个位置，并对每个位置用累计权重
`cdf < position` 的严格比较查找第一个累计权重不小于该位置的父槽。每个子槽使用
`ceil(log2(P))` 次二分比较，不构造 `P*P` 选择矩阵；这里的 `O(log P)` 只指每个子槽的查找，
不把输出 `P` 个子槽的总成本写成 `O(log P)`。

新版设计数据仍由官方 `rnn-sp` seed 100 主体分别与四个已准入伙伴运行 20 个完整 400 步
回合，共 80 回合。历史收集仍使用温度 1 的无探查策略，只产生候选无关的官方历史；但回合
随机数和两条过滤重放流使用新的 `r015_design_role_isolation_v2` 命名空间，与旧 80 条历史、
准入、试点和正式数据全部不相交。旧历史只能作故障复现和静态接线核查。

每个候选继续使用三项机械统计：零支持关闭率（S1）不超过 2%；两条重放流在各咨询点的四原型
后验总变差距离第 90 百分位（S2）不超过 0.05；全部咨询点、两次重放、各原型的重采样前
`ESS/P` 第 10 百分位（S3）不低于 0.2。经验百分位仍用不插值的最近秩规则，排序后取
第 `ceil(p*n)` 个值。候选仍按粒子数升序、同一粒子数内先自适应后每步排列；每个候选原子写完
完整证据或不可逆 S1 失败证据后立即机械判定，第一个同时通过者使更高候选不再运行。固定分母为 80 个设计回合，
所以同一候选出现第 2 个关闭回合时，S1 已不可逆地超过 2%；实现可以停止该候选并记录明确的
S1 失败，但不得读取尚未产生的 S2 或 S3 来选择下一候选。全部六个候选失败时仍记录
`filter_design_precision_infeasible` 并停止，不得扩网格或改门槛。

设备随机键合同升级为 `r015_filter_device_fold_in_keys_v2`。每条初始化根键只绑定过滤重放流和
全局设计序号，明确移除 `P` 与重采样时机；再在设备内依次折入原型、已接受提议序号、环境步、
用途、动作或环境结果及重采样子槽。`P=64/128/256` 使用同一条件化提议序列的前缀，两种重采样
时机在首次实际分叉前共享同一创新；分叉后的键从已接受提议序号和各自当前父子来源继续派生。
宿主不再逐粒子逐步计算 SHA-256。该规则改变旧版实际随机流，所以只能用于新的独立设计数据，
不能声称与旧证据逐位相同。设备执行标识为 `r015_filter_jit_scan_vmap_v2`，微批日程标识为
`fixed_4096_parent_particle_slots_v1`：微批次（microbatch）表示一次
固定宽度设备调用处理的一组“设计历史×过滤重放流”车道，每批固定 4,096 个父粒子槽并分成
四个各 1,024 槽的原型组。`P=64/128/256` 时每批分别为 16/8/4 条车道；每个原型 checkpoint 只前向自己的
父粒子组，不在全部槽上运行四个网络后再选择结果。过滤候选阶段不得初始化或推进五个延续
控制器成员，因为它们不参与过滤器三项统计；规划和实际执行阶段仍按 §2.3 运行它们。微批结果
按全局车道序号合并，计数求和、吞吐按总真实转移除以总墙钟重算，不能改变百分位输入顺序。

条件化开局粒子前缀缓存使用 schema
`path_c_r015_conditioned_opening_particle_prefix_cache_v1` 和合同
`r015_shared_conditioned_opening_256_particle_prefix_v1`。对同一“设计历史×过滤重放流”，接受
粒子的规范序列按 64、128、256 个槽递增物化，每个槽至多生成一次，较小粒子数只取同一序列
前缀。两种重采样时机只能共享这段条件化开局；任何扫描中间状态或重采样后状态都不得进入缓存。
缓存必须绑定当前协议、源码闭包、设计历史和初始化根键；崩溃恢复时不得信任缺少这些绑定的
磁盘缓存。该缓存只消除重复开局提议，不改变粒子序列或任何选择统计。

当前粒子数、重采样时机和新版证据摘要仍为 `pending`；静态夹具不能代替新的设计数据。

评估器可以另算使用完整联合轨迹的特权后验，但它只能诊断回应词表损失了多少信息，不能参与 `A1`、`A2-mask` 或 `A2-use` 的动作选择。

### 2.2 与主体信息集相容的分支

在咨询点，控制器从 `q_t(U)` 独立抽取或枚举完整隐藏状态，并为每个样本重构与同一个 `h_t^ego` 相容的模拟器状态。每条延续保持自己的伙伴隐藏状态、环境状态和随机数，禁止把不同隐藏状态的历史前缀与延续拼接。

动作价值写为

`Q_bar(q,h,u) = E_{U ~ q, future}[return | h_t^ego=h, U, u]`。

有限分叉只产生该量的近似。数据前第二次修订（2026-07-15）把分支抽样规则冻结为
`sampled_hidden_state_branches_v1`。粒子按过滤器产生的规范序列排列并按当前权重归一化；由
§5 六坐标规划随机键的前 64 位得到 `u in [0,1)`，R 个系统抽样位置为 `(u+j)/R`。
2R 使用相位 `frac(2u)`，第 j 个 R 样本对应 2R 中 `2j+floor(2u)` 的样本，因此 R 样本严格
包含在 2R 样本中。每个估计中的样本等权；重复抽到同一粒子仍是两个样本槽。基线与六个脚本
共享同一批完整隐藏状态和对应未来随机流。R 条分支是每个价值估计的总样本数，不再按粒子数
重复实例化。

每条分支的未来随机数证据字段固定为 `future_random_root_key`、
`future_random_derivation_contract_id`、`future_random_step_count` 和
`future_random_sequence_sha256`，分别表示根键、冻结的派生合同、序列步数和完整序列 SHA-256。完整
序列按环境步顺序组成规范 JSON 后用 `sha256_canonical_json_v1` 计算摘要；正式证据不得逐步
展开或保存 `future_random_keys`。验证器必须从根键和派生合同重建完整序列，核对长度与摘要，
所以该压缩只改变证据表示，不改变任何分支随机数或重放义务。

规划分支候选固定为 `R in {2,4,8}`。在选定过滤器后的设计历史
中，先按回合序号、同序号内按伙伴原型编号轮换、再按环境步排序，取最前 200 个完整咨询点；
若不足 200 点则机械失败。轮换排序保证四个伙伴的信念域在选点中均衡出现（数据前修订
2026-07-15，避免字典序单伙伴独占选点；冻结标识
`first_200_design_consultations_partner_interleaved_v2`，每个选点须携带伙伴原型编号与
回合序号字段）。
规划分支数选择固定使用新版第一条过滤随机流
`r015_filter_repeat_0_20260718_v2`；第二条过滤随机流只计算重复运行稳定性，不能在看到规划
结果后择优，也不能与第一条合并成新的后验。
每点用共用随机数比较 `R` 与 `2R` 的完整剩余回合规划，覆盖六个注册脚本、基线动作和四个
原型。`2、4、8、16` 的系统样本递归嵌套；一次计算 2R 样本后，R 的估计直接由其中登记的 R
个样本重新赋予 `1/R` 权重得到，不重复运行。网格规则冻结为
`lazy_ascending_first_pass`：先计算 4 个唯一样本并比较 2 与 4；未通过时复用全部已核验分支，
只增加样本到 8，再按同样规则增加到 16。首个通过后不得生成更高档证据。

单点只有在“回应屏蔽参照动作”和“探查决定（候选编号或不探查）”两个字段都完全相同时才计为
一致。按 `R` 升序取第一个一致率至少 95% 的值；`R=8` 与 16 条分支仍不过时记录
`planning_design_precision_infeasible` 并交回 Type-B。规划语义成本仍须逐咨询点记录，包括
真实逐轨迹环境转移、配对后缀的批量车道时间步和分支头粒子转移。长度桶指剩余规划步数相同的
咨询点集合；编译批次调用数、活动批量大小、墙钟时间和真实转移吞吐不分摊到单个咨询点，而在
每个规划候选的顶层按长度桶和设备批次记录。候选总吞吐由该候选的真实环境转移总数除以实际
总墙钟重算；跨咨询点 `vmap` 不得用平均数或比例制造逐点执行读数。批量调用数不得冒充真实
环境转移数。正式试点和正式数据都不得再次改变控制器。

### 2.3 成对的回应使用分数

候选脚本 `p` 结束后的规范化序列记为 `h_after`。冻结字段投影 `P_mask^(p,t)`，删除“由本次候选脚本在该时间窗生成”的 `ResponseSummarySpecV1` 序列化坐标，以及显式复制、重编码或依赖该坐标的所有非官方派生字段和循环状态写入；它不改写原始官方局部观测、主体动作、回报或回合边界。其他派生字段只有在冻结依赖图确认其不携带当前候选回应摘要的显式别名后才能保留。定义

`x = P_mask^(p,t)(h_after)`，

`y = Y^(p,t)(h_after)`。

因此 `x` 是两个实验组共同看到的序列化历史，`y` 是只允许进入使用组的当前候选回应记号。投影必须同时作用于信念更新输入、共享延续控制器输入和它们的循环状态写入；不得把含 `y` 或其非官方别名的完整 `h_after` 从旁路传给 `B_mask` 或 `C`。本次候选窗口之后新产生的被动回应记号按同一规则同时提供给两组。原始官方局部观测始终保留，所以 `x` 仍可能隐含足以重新计算 `y` 的证据；这正是本端点只识别显式路由效应的原因。

令 `B_use(q,x,y)` 和 `B_mask(q,x)` 是预先冻结的两个信念更新接口。数据前补全
（2026-07-15）把共享延续控制器 `C(q,x)` 具体注册为
`map_prototype_committed_cook_v1`。MAP（maximum a posteriori）表示当前后验概率最大的伙伴原型。
控制器在每个环境步检查四原型后验：若最大值唯一，就让该原型自己的冻结 checkpoint 在
`agent_1` 厨师席按 `official_flax_categorical_actor_v1`、温度 1 产生动作；若最大值精确并列
（包括均匀开局），就使用官方 `rnn-sp` seed 100 主体基线。并列只按最大后验值的精确相等
判断，不用原型编号打破并列。

四个原型和主体基线共五个库成员的循环隐藏状态从回合开始逐步并行推进，每步都读取同一主体
席位的官方局部历史。MAP 改变时直接使用新成员已经推进到当前步的隐藏状态，绝不清零重置；
五次前向都计入逐咨询点的规划语义成本，但不据此伪造逐点设备调用或墙钟。该规则只读 `q_t`
与主体自己的投影后官方历史，四个原型
checkpoint 是公开登记的信念支持而非隐藏身份。回应记号改变 MAP 时会改变后续约定执行者，
因此回应通道能够真实影响 `Delta_response`；规则不增加训练，每个库成员都来自已准入产物。
规划和真实配对执行必须调用同一个 `map_prototype_committed_cook_v1` 成员选择函数，不能在
规划中替换成别的延续策略。但两者的信念更新时间明确不同：真实回合每个环境步在线更新信念
并重新选择成员；规划分支按下一段冻结规则只在分支头选择一次。旧的“规划与执行完全同构”
表述作废。

规划信念规则冻结为 `frozen_belief_branch_continuation_v1`。基线分支在咨询点按 `q_t` 选择
一次成员并保持到回合结束。探查分支先执行同一个共享脚本步骤，保留任务转移 `x`；随后只在
分支头计算一次 `B_mask(q_t,x)` 或 `B_use(q_t,x,y)`，按所得信念选择成员，并在余下后缀保持
该成员不变。分支后缀不得再次运行过滤器或切换成员。探查共享步骤仍从咨询点已有的五成员当前
循环状态推进，承诺后直接采用所选成员的当前状态，不得清零。

唯一序列化接口差异仍是 `B_use` 额外接收注册记号 `y`。在同一批隐藏状态与未来随机数分支上，直接估计这两个受限控制器的完整延续回报：

`J_use(p) = E[return | h_t^ego, execute p, then C(B_use(q_t,x,y), x)]`，

`J_mask(p) = E[return | h_t^ego, execute p, then C(B_mask(q_t,x), x)]`。

因此 `J_use-J_mask` 可以为正、零或负，并且只表示显式摘要接口对该冻结控制器的帮助。若它为正，允许措辞是“注册回应通道帮助该控制器使用官方历史”；不得改写成“不受架构限制的伙伴信息价值”。

这项数据前修订不改变三个实验组的原始回报差定义或正式统计量，但会固定一个新的规划近似，
因此可能改变控制器是否探查。只能说估计对象仍是修订后注册控制器的已执行回报差，不能声称
另一种规划信念传播会产生逐字节相同轨迹。§1.4 的近似误差条款适用于该选择。

令回应屏蔽参照价值为

`V_mask(h) = max{V_base(h), max_{p in P_safe(h)} J_mask(p)}`。

则

`I_response(p) = J_use(p) - J_mask(p)`，

`C_task(p) = V_mask(h) - J_mask(p)`，

`S_seq(p) = I_response(p) - C_task(p) = J_use(p) - V_mask(h)`。

控制器只在 `S_seq(p)>0`、仍处于前 100 步、尚未执行过探查且候选通过安全检查时，执行最高分脚本。`A2-use` 与 `A2-mask` 由同一个探查前评分选择同一个 `p`；二者只在是否允许使用 `y` 上不同。

### 2.4 安全的可检验定义

R015 的正式安全事件是错误交付。配方指示器激活产生的 `-5` 是可预期任务成本，已经进入原始回报、`J_use`、`J_mask` 和 `Delta_net`，不能再次作为安全失败。

价值分叉和安全验证使用独立随机流。R015 的正式支持固定为 `K=4`，正式数据至多有
`N_rounds_max=2500` 轮，每轮每个原型一个配对块，因此每个原型至多有
`N_rounds_max` 个正式块，整个正式审计最多有 `K*N_rounds_max` 个回合级候选。每个正式回合
只允许一次安全裁决：控制器在首个出现正分候选的咨询点选取分数最高者，并在四个支持原型条件下
分别运行 `R_safety` 次独立安全分支。只有当同一官方历史在四个原型下都具有正后验支持并能
重构相容隐藏状态时，候选才可进入安全裁决；否则直接拒绝。任一条件观察到错误交付时，该回合
不执行探查，也不改试其他候选。

整个正式审计最多进行

`M_safety = K^2 * N_rounds_max`

个“候选—支持原型”安全比较。对风险上限 `tau=0.05`，统一冻结

`R_safety = ceil(log(alpha_safety / M_safety) / log(1 - tau))`，

其中 `alpha_safety=0.025`。每项比较都必须观察到零次错误交付。若某项真实错误交付概率大于 `tau`，它通过零事件检查的概率至多为 `(1-tau)^R_safety`；对至多 `M_safety` 项比较使用并集上界，整个正式审计错误放行任一此类候选的概率不超过 `alpha_safety`。对“观察零事件才放行”这条冻结规则，公式给出的 `R_safety` 也是最小整数：少一次重复就会使单项最坏通过概率大于 `alpha_safety/M_safety`，因而无法得到同一总体保证。该保证覆盖本次正式审计实际可能裁决的全部候选，但不外推到未进入本审计的历史、伙伴或候选。安全分支必须相互独立，并与候选评分和正式回合随机流独立。

## 3. 伙伴支持、抽样与统计

### 3.1 三类伙伴对象

- **伙伴原型：** 一个具体冻结 checkpoint。
- **伙伴族：** 由相同训练算法、训练目标和约定生成机制产生的策略集合；只改变 seed 不产生新伙伴族。
- **held-out 伙伴族：** 没有任何成员进入回应模型、价值模型、过滤器支持、校准、阈值选择、R015 支持或方法选择的完整伙伴族。

R015 的正式固定支持恰为四个原型，来自两个伙伴族且每族两个原型；每个原型达到同一冻结能力标准。进入 R015 支持的伙伴不是 held-out。R015 的统计结论条件于该固定支持，不外推到未见伙伴族。

官方 checkpoint 包装器同时绑定文件 SHA-256 与 Flax 参数树权重 SHA-256。权重摘要按展平后的
完整键路径排序，逐叶纳入键路径、数据类型、形状和连续原始字节；它排除 checkpoint 容器和
metadata，所以重新序列化或只改 metadata 不能制造第二个策略。正式支持要求四个文件
SHA-256、四个模型权重 SHA-256 和四个训练运行标识分别互异。没有这种权重证明的旧版
checkpoint 只可作历史非正式读取，不能进入 R015 正式来源核验，也不改写升级。

2026-07-14 签署的正式登记改为两个官方伙伴族。第一族是官方循环 Independent Proximal
Policy Optimization 自博弈变体 `rnn-sp`，seed 为 101/102；第二族是官方 Other-Play
变体 `rnn-op`，seed 为 201/202。Other-Play 指训练时使用环境对称变换来减少固定约定依赖。
两族共享官方训练算法与目标，但约定生成机制不同。主体基线是独立的官方 `rnn-sp` seed 100，
不进入四个支持原型。我方 torch 训练器生成的旧候选及其失败准入证据只保留作历史诊断，退出
新的正式支持链。

### 3.2 配对回合和等权估计

一个完整配对块由同一个伙伴原型、固定主体席位、初始状态和回合随机数下的 `A1`、
`A2-mask`、`A2-use` 构成。主体恒为 `agent_1` 厨师，伙伴恒为 `agent_0` 信号者；`A0` 可共享
同一块作诊断。任一正式实验组回合失效时，整个配对块作废并整体替换。

正式抽样日程固定为 `iid_round_vectors_ego_cook_seat_with_prefrozen_replacements_v4`。这里的
预冻结替换表示：在任何正式数据产生前，`path_c_r015_formal_sampling_schedule_v4` 为每个
`(round_index, prototype_id)` 坐标绑定不变的 `audit_unit_id`，并按
`mechanical_attempt_index=0,...,31`
依次绑定恰好 32 个 `episode_seed`。每个槽只把根 seed、轮、原型及尝试编号组成登记坐标，计算一次
SHA-256 并取低 32 位；不同槽的 32 位值允许偶然相同，且不得查看已有槽或因碰撞重抽。执行总是先用编号 0；只有整个配对块被机械判为失效时
才能推进到下一个已绑定 seed。推进决定不得读取回报、配对差、
触发状态、效应值或其他结果，也不得改变该坐标的 `audit_unit_id`。32 个尝试全部机械失效时终止整个正式审计；不得临时派生
第 33 个 seed，不得换原型或重排轮次。失效尝试不进入正式估计量，唯一进入正式数据的块必须
来自该坐标首个机械有效的已绑定尝试。

正式块账本是按日程顺序记录每个成功块路径、文件 SHA-256、所选尝试编号和运行绑定摘要的
逐行文件；机械失效账本另按从 0 开始的连续前缀记录每次失败。最终数据集
`path_c_r015_formal_dataset_v3` 必须同时绑定这两个
账本的绝对路径和文件 SHA-256，并绑定同一个运行摘要；独立裁决器重新读取两份账本和每个成功
块，只有所选尝试紧接完整失效前缀，且 seed、轮—原型坐标、运行摘要和块摘要全部一致时才接受。
正式运行还必须把本次计算得到的运行摘要作为外部预期值传给裁决器；数据集自报一个内部自洽的
摘要不能替代这项核对，已有数据集也必须与当前账本重新组装出的字节完全相同。
成功块文件本身也写入运行摘要，因此崩溃后发现尚无成功账本行的孤立块时，恢复程序必须先核对
该摘要，并以同一冻结 request 调用生产器重新生成后逐项比较。比较保留全部科学证据、随机键、
轨迹、决定、真实转移数、编译调用数和活动批宽，只允许两个由机器调度决定的非负有限耗时字段
不同；不能只信任孤立块自报的触发标记，也不能把另一套运行产生的块补入账本。唯一效应查看文件先以独占创建记录“裁决前已消费”；
裁决结果和终局文件原子落盘后，再把同一文件原子更新为 `completed`，绑定终局文件 SHA-256 与
裁决内容 SHA-256。终局文件只绑定更新前的消费记录摘要，完成记录再绑定终局摘要，因此不存在
相互引用的摘要循环；恢复时必须从账本和次数 checkpoint 重算提前停止，或同时核对正式数据集、
两份账本、全部 checkpoint、终局摘要和完成记录后才能返回已有终局。

对端点 `e`、原型 `k` 和正式轮 `r` 记配对差为 `D_{e,k,r}`。四个原型在每一轮各提供一个
配对块，正式上限同为 `N_rounds_max`，估计量为

`Delta_hat_e = (1/(K*N_rounds_max)) * sum_r sum_k D_{e,k,r}`。

这等价于先求每个原型的均值再等权平均。四个原型是固定分层，不是四个足以支持总体推广的
随机聚类。轮向量必须按同一规则独立生成，且每个配对块都把主体固定在 `agent_1` 厨师席；
不得按任何运行后计数、触发状态或结果选择正式坐标、安排替换 seed 或重排轮次；唯一允许的
替换是上一段规定的机械失效后按编号推进。同一轮四个原型的效应值可以相关，实验组内的共同随机数只
存在于同一个配对块中。§3.4 的零触发乘积界另要求四个原型的触发前缀相互独立：抽样清单必须
给每个原型分配独立的初始状态与实际回合随机流，触发前不得使用轮级共享随机源。这个额外条件
只服务零触发乘积界，不要求触发后的效应值相互独立。违反轮间独立性或触发前缀独立性时拒绝
正式读数。按原型报告均值、标准差，并对完整配对块做分层 bootstrap，但这些只作描述和稳健性诊断。

### 3.3 试点、正式轮次和一次效应查看

试点为每个原型 20 个完整配对块，共 80 块，使用与准入、设计数据和正式数据均不相交的新回合
随机数。它必须完成 §5 全部九项接线核查，并输出配对差的描述性离散程度、由逐咨询点汇总的
逐块规划语义成本、在冻结规划候选顶层按长度桶和设备批次记录的规划吞吐，以及零探查可解释性
计数。跨点批量执行的设备读数不得伪分摊到单块或单点。试点均值、符号和方差都不决定正式轮数
或任何效应判定，试点数据不进入正式区间。

[R015_RETURN_BOUND_DERIVATION.md](R015_RETURN_BOUND_DERIVATION.md) §5–§6 已记录旧版
Hoeffding 样本量规则要求每原型 259,850 个配对块，因而触发“当前设计精度不可行”条款。
该规则及其匹配下界论证从正式路径退休，不再由试点方差替代。

正式抽样单位改为“轮”：每轮对四个固定原型各生成一个配对块，轮向量按冻结规则独立同分布；
抽样清单绑定 `iid_round_vectors_ego_cook_seat_with_prefrozen_replacements_v4`，表示主体恒为
`agent_1` 厨师，每个轮—原型坐标在数据前绑定 32 个有序、逐槽直接派生且不因值碰撞重抽的 seed，并且只能因整块机械
失效按编号推进。任何运行后计数、触发状态或结果都不得选择 seed 或轮次。同一轮内四个原型仍
是等权固定分层，效应值不要求彼此独立。四个触发前缀必须按 §3.2 使用独立随机流，
这是零触发乘积界的可机械核查前提。对端点 `e`，第 `r` 轮的平均配对差为

`D_bar_{e,r} = (1/K) * sum_k D_{e,r,k}`。

因此 `E[D_bar_e]=Delta_e`，严格保持 §3.2 的四原型等权估计对象。正式上限冻结为
`N_rounds_max=2500` 轮，即四原型合计 10,000 个配对块。三个正式实验组按每块 400 步计算约
需 `10000*3*400=12,000,000` 个环境步；规划分叉不计入该数，必须另报。
另报时逐咨询点保留语义成本，设备运行读数只按每个规划候选的长度桶和设备批次汇总，二者都
不得进入正式效应统计。

未触发探查的配对块中，三个正式实验组的完整轨迹必须逐字节相同，所有配对差恰为零。触发
探查的配对块中，三个实验组在触发时刻前的完整前缀相同，前缀奖励在配对差中抵消。`t_p` 表示
已经完成 `t_p` 个环境步后的咨询边界，满足 `1<=t_p<=100`；嵌入轨迹使用从 0 开始的记录编号，
所以共同前缀是记录 0 到 `t_p-1`，分支从记录 `t_p` 开始，其后最多 `400-t_p<=399` 步。仅由当前机械检查和锅吞吐
事实不能把任意后缀限制为 19 次交付，因为后缀可能继承触发前已开始烹饪或已完成但尚未交付的
汤；因此可证明的统一配对差界仍为

`D_{e,r,k} in [-800,800]`，从而 `D_bar_{e,r} in [-800,800]`，区间宽度为 1600。

这个范围只在 §5 的逐字节锁步不变量通过时有效；任一违反都使整个配对块失效，并按 §3.2
整块替换。`N_rounds_max` 不是按试点方差求出的把握度样本量，而是预先冻结的单次效应查看预算。

### 3.4 empirical Bernstein 区间、触发次数提前停止和错误率

主证书只在 `N=N_rounds_max` 时正式查看一次 `Delta_net` 和 `Delta_response` 的配对差。对每个
端点的 `D_bar_{e,r}` 序列使用 Maurer–Pontil empirical Bernstein 双侧区间，标识符冻结为
`maurer_pontil_empirical_bernstein_bounded_v1`。令 `V_N` 为这 `N` 个轮均值的无偏样本方差，
`a=-800`、`b=800`，则半宽为

`r_EB = sqrt(2*V_N*ln(2/alpha_EB)/N) + 7*(b-a)*ln(2/alpha_EB)/(3*(N-1))`。

`Delta_net` 和 `Delta_response` 各使用 `alpha_EB=0.010`，区间分别为
`[Delta_hat_e-r_EB,Delta_hat_e+r_EB]`，并截到 `[-800,800]`。该区间分布无关；共同随机数配对
产生的未触发块会使 `V_N` 随低触发率收缩，这正是本设计使用正式样本自身方差的方式。Welch
区间和分层 bootstrap 仍只作诊断，不参与判定。

另设只读取触发次数的提前停止规则。令 `rho_k=P(触发探查|原型 k)`，
`rho_bar=(1/K)*sum_k rho_k`。因为未触发块的配对差恰为零且触发块的绝对配对差不超过 800，

`|Delta_net| <= 800*rho_bar`，`|Delta_response| <= 800*rho_bar`。

只在轮数 `{200,400,800,1600,2500}` 查看触发次数。触发次数证书族的错误率
`alpha_rho=0.005` 由 Bonferroni 等分到五次，每次 `alpha_rho_j=0.001`。若 `N` 轮后的总触发
次数为零，则

`rho_bar_U = -ln(alpha_rho_j)/(N*K)`。

这是因为 §3.2 已机械绑定四个原型的触发前缀独立性，所以
`P(零触发)=prod_k(1-rho_k)^N <= exp(-N*K*rho_bar)`。若抽样清单没有证明该独立性，正式
触发次数证书拒绝读数。若总触发次数非零，则对每个
原型用单侧精确 Clopper–Pearson 上界，单个原型的错误率为 `alpha_rho_j/K=0.00025`，再取四个
上界的等权平均作为 `rho_bar_U`。当且仅当 `800*rho_bar_U<m` 时，提前给出“注册控制器达不到
门槛”的判定，并记录触发该判定的 checkpoint。

提前停止检查不读取任何 `D`、回报、效应均值或效应区间；它只读取每个原型在已经完成轮次中的
触发次数，而触发标记由共享前缀在看到该块结果前确定。因此这些 checkpoint 不是效应查看。
若任一 checkpoint 触发提前停止，就不计算效应区间；若始终未触发，两个效应区间只在
`N_rounds_max` 计算一次。这保持“一次正式效应查看”的纪律。本次查看后无论结果如何都不得
追加轮次或重看；若项目决定在更大轮数预算下重测，必须另立新实验编号、新冻结规则和全新
正式数据。

总错误率仍为 0.05：安全证书族使用 0.025，`Delta_net` 区间使用 0.010，
`Delta_response` 区间使用 0.010，触发次数提前停止证书族使用 0.005。由并集上界，“安全证书
正确、两个效应区间覆盖且提前停止证书正确”的概率至少为 0.95。

对于任何固定有限样本，必须保留不可裁决结果。即使使用方差自适应区间，仍可构造均值分别位于
边界两侧 `m-epsilon` 与 `m+epsilon` 的有界分布，使有限 `N` 的区分信息随
`N*epsilon^2` 缩小；取 `epsilon` 与 `N^(-1/2)` 同阶，任何规则都不能同时保证两侧低错误率。
因此不可裁决不是测量失败，而是有限数据的必要结果。

## 4. 判定与允许措辞

记两个同时区间为 `[L_net,U_net]` 和 `[L_response,U_response]`。

| 读数 | 科学结论 | 项目含义 |
|---|---|---|
| `L_net > m` 且 `L_response > 0` | 冻结伙伴支持上存在一个官方观测可实现、注册回应通道确实承重且净收益具有实际意义的单次安全探查控制器 | 支持继续实现学习版本 |
| `U_net < m`，且只在 `N_rounds_max` 的单次效应查看中判定 | 当前注册单次探查控制器达不到实际意义门槛 | 记录为“正式区间上界低于门槛”；可作为停止当前实现方向的决策依据，不能宣称基底无机会 |
| 某个冻结 checkpoint 满足 `800*rho_bar_U<m` | 当前注册单次探查控制器因触发率过低而不可能达到实际意义门槛 | 记录为“触发次数上界低于门槛”及具体 checkpoint；不能宣称基底无机会 |
| 其余情况 | 当前精度下不可裁决 | 保留区间和原始数据，不写成接近显著或等效 |
| 经证明的 `Delta_upper` 上置信界 `< m` | 在明确写出的完整信息策略类别和固定伙伴支持内，任何官方观测控制器相对 `A1` 都不可能获得门槛收益 | 才允许作该范围内的保守否定；当前尚无此对象 |

若 `L_net>m` 但 `L_response<=0`，只说明探查动作组合提高了任务回报，不能把收益归因于注册回应通道。若 `L_response>0` 但 `L_net<=m`，说明该通道有增量决策价值，但成本后净收益未达到项目门槛。

R015 的项目停止决定和科学否定必须分开记录。项目可以基于成本、时间和当前控制器结果停止投入，但不能把资源决定改写成“OvercookedV2 不存在探查机会”。

## 5. 接线核查

以下核查只判断实现是否遵守规范，不读取科学效应：

1. **信息隔离：** 两条具有相同 `h_t^ego`、不同完整 `U_t` 的记录必须向正式控制器提供逐字节相同输入；记录任何读取完整网格、不可见配方、伙伴私有观测、真实身份或伙伴隐藏状态的路径即拒绝读数。
2. **过滤器核对：** 精确模式检查概率归一化和小规模枚举一致性；近似模式须证明每个开局粒子
   是独立接受的条件样本而非复制补槽，逐父粒子的六动作及相关环境结果边缘似然与小规模枚举
   一致，条件后继确实来自相容分布，ESS 由重采样前父权重和固定 `P` 重算。有限粒子云零支持
   只能由所有父粒子的边缘似然为零得到，不能把它写成原型模型零概率。两条过滤流的重复稳定性
   仍须核对；真实原型后验不要求逐轨迹单调上升。设备检查还须绑定 4,096 父粒子槽、按原型
   网络分组、候选阶段不运行五个延续成员，以及严格系统重采样与逐条参照一致。
3. **回应使用配对：** `A2-use` 与 `A2-mask` 在探查结束前的动作、共同历史 `x` 和随机数完全相同；探查结束后，`B_mask`、`C` 及其循环状态都只能读取 `P_mask^(p,t)(h_after)`，唯一允许的序列化接口差异是 `y` 是否额外进入 `B_use`。五个库成员的循环状态必须从开局连续推进，真实执行中的 MAP 切换不得清零。规划重放必须证明分支头所选成员与同一选择函数一致，且后缀信念摘要和成员编号保持不变；真实执行重放必须证明每步在线更新仍在。原始局部观测不被改写，其中已经公开的反应式信息由两个实验组共同使用。
4. **随机数命名：** 正式审计随机键仍至少由 `(审计单元, 伙伴原型, 回合随机数, 用途, 环境步,
   分支编号)` 导出；实际回合、价值规划、分数估计和安全验证使用不同用途名称。新版过滤设计
   使用 `r015_filter_device_fold_in_keys_v2`：初始化根键只绑定过滤重放流和全局设计序号，原型、
   已接受提议序号、环境步、用途和后继坐标在设备内依次折入；不同 `P` 使用同一提议前缀，
   两种重采样时机在分叉前共享创新。每轮四个原型的触发前缀仍使用不同实际回合随机流，且不
   存在触发前的轮级共享随机源。规划分支证据只保存 §2.2 固定的四个字段，禁止逐步展开
   `future_random_keys`；独立重放必须由这四项重建并核对序列。
5. **零探查可解释：** 候选评估次数、安全拒绝数、非正分数和窗口过期数全部记录。全部零执行在接线正常时是结果，不自动归为软件失败。
6. **规模回读：** 每个原型的试点块、正式块、有效配对块、价值分支和安全分支从产物重算，不信
   配置意图。规划语义成本须逐咨询点重算；编译批次调用、活动批量、墙钟和吞吐只能在规划候选
   顶层按长度桶与设备批次核对，验证器拒绝跨咨询点 `vmap` 后复制或分摊出的单点设备读数。
7. **逐字节锁步：** 未触发探查的配对块必须从嵌入的 400 步记录重算出三个正式实验组完整轨迹
   哈希相同，并重算 `Delta_net=Delta_response=Delta_cost=0`；触发探查的配对块必须重算三个
   实验组在 `t_p` 前的完整轨迹前缀哈希相同，并验证 `1<=t_p<=100`。任一违反使整个块失效，
   按 §3.2 整块替换。
8. **触发标记共享：** 触发标记是由三个正式实验组共同前缀计算出的块级属性，必须与共享的
   首次正分选择、安全放行和实际探查记录一致；不允许各实验组分别自报触发状态。
9. **提前停止输入隔离：** 触发次数提前停止器的输入只能含 checkpoint 轮数和四个原型的触发
   次数。输入模式出现任何 `D`、回报、效应均值、方差或区间字段时，验证器必须拒绝。
