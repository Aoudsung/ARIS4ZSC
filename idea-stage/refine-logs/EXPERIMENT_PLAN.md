# Experiment Plan — Path C 对齐已发表基准后的正式实验

**研究问题：** 在协作智能体只能使用官方局部历史时，按“启用注册回应摘要通道的受限控制器价值减去相对最佳通道屏蔽动作的任务价值”选择探查，能否提高与未见伙伴协作时的回报？
**方法主线：** Path C 使用只接受时序差分价值梯度的循环表示，并以 `J_use−V_mask` 选择普通任务动作作为探查；旧归一化动作相对价值分歧只保留为历史消融。
**日期：** 2026-07-13
**执行边界：** 本文件只修订实验方向，不授权本地或远端运行。项目执行仍须用户明确授权，并且只能在 `zsc-customer` 远端进行。

> **2026-07-13 适用范围更新：** 本文件保留公开基准和成本对齐细节；当前实验顺序以
> [PATH_C_EXECUTION_PLAN.md](PATH_C_EXECUTION_PLAN.md) 为准。R015 先测官方观测下注册回应
> 通道的增量使用效应与净收益；该通道效应不等于全部伙伴信息价值，且 R015 是资源排序而非
> 通用启动条件。Test Time Wide 只是布局复现；投稿级范围
> 另需独立 held-out 伙伴族面板和 Hanabi 证据。当前 seed 101/102 只属于同一伙伴族。

## 1. 对原 M2 的裁决

原 M2“生成并固定基线”不再成立，原因如下：

1. `full_history_rnn`、`rnn_residualized`、exact/HMM/particle belief filter 都是本项目自建系统，不是已发表方法的标准实现。它们不能作为论文主表中证明优于现有研究的主要对照。
2. random probe、no probe、删除 residualization 等比较只回答“Path C 的哪个组件有效”，属于消融实验，不回答“是否超过现有研究”。
3. 在 design split 上从一组自建系统中选择最优者，会把大量计算花在内部模型选择上，却仍不能建立相对已发表工作的外部竞争力。

修订后不再训练一整套自建主基线。主表先对齐已发表方法与公开协议；自建比较只在主结果之后作为消融实验。

## 3. 选定布局、指标与环境流程

### 3.1 主布局

- 主布局：`test_time_simple`。
- 预先指定的复现实验：`test_time_wide`。
- `grounded_coord_simple` 只用于检查有明确信息通道时的方法行为。
- `asymm_advantages` 降为内部消融或旧结果兼容检查，不再承担论文主结果。

两个主布局均直接来自官方仓库。环境参数固定为：

- `ENV_NAME=overcooked_v2`；
- `max_steps=400`（官方环境默认值，评估器完整运行 400 步）；
- `agent_view_size=2`；
- `negative_rewards=True`；
- `random_agent_positions=True`；
- `sample_recipe_on_delivery=True`；
- `indicate_successful_delivery=True`。

官方配置见 [`test_time_simple.yaml`](https://github.com/overcookedv2/experiments/blob/main/experiments/overcooked_v2_experiments/ppo/config/env/test_time_simple.yaml) 和 [`test_time_wide.yaml`](https://github.com/overcookedv2/experiments/blob/main/experiments/overcooked_v2_experiments/ppo/config/env/test_time_wide.yaml)。

### 3.2 指标顺序

1. **主指标：平均 XP episode return。** 这是与已发表工作直接对齐的指标。
2. **必须同时报告：SP episode return 与 SP−XP gap。** 只看 gap 会奖励“SP 和 XP 都很低”的退化方法，因此 gap 不能替代 XP。
3. **方法支持指标：扣除探针成本后的回报—探针预算曲线。** 它回答主动探针是否更高效，但降为支持结果，不再替代标准 XP 回报。
4. **消融指标：value-directed、random probe 与 no probe 的差异。** 它只证明组件贡献。
5. **ICRL4AHT 扩展指标：逐 episode 适应曲线与适应增益。** 只在采用其完整伙伴协议时报告。

所有主表结果按 10 个独立训练 seed、90 个有向跨 seed 配对、每个配对 500 个 episode
汇总；同时报告均值、标准差和 95% 置信区间。双方玩家位置顺序按官方
[`visualize_ppo.py`](https://github.com/overcookedv2/experiments/blob/main/experiments/overcooked_v2_experiments/ppo/utils/visualize_ppo.py)
的全排列方式纳入，不能只选择有利角色。

为了和 Table 2 直接对齐，先按官方配对单元重算其均值与标准差。额外的 95% 置信区间不把
45,000 个 XP episode 错当成彼此独立。同一个训练 seed 会同时出现在主体和伙伴位置，因此
使用训练单元节点重采样：每次对 10 个训练单元索引有放回抽样一次，所得计数同时作为两种
位置的权重，只用 `i!=j` 的原有有向配对重算均值；少于两个不同训练单元时按下一预生成随机
键重抽。固定 9,999 次有效重采样和运行前登记的随机种子。该区间用于描述 Path C 自身的
不确定性，不伪造与论文汇总数字之间的显著性检验。

### 3.3 与已发表数字比较的措辞

- 若只取得论文中的均值和标准差，结果可写为“高于已发表参照值”，但不能写成“统计显著优于当前最佳公开结果”。
- 只有获得原作者逐 seed 数据或公开 checkpoint，并在同一 evaluator 中重算后，才检验统计优越性。
- 这一限制只约束论文措辞，不阻止实验启动，也不要求额外训练基线。

## 5. 实验块

### B0：公开协议静态对齐

- 核对官方布局名称、环境参数、训练步数、seed 数、XP 配对方式、每配对 episode 数和聚合公式。
- 固定使用最终 checkpoint，不按测试回报挑选 checkpoint；核对官方 evaluator 的随机动作采样、
  400 步 episode 和 90 个有向跨 seed 配对。
- 把 ICLR 2025 Table 2 的 Test Time 结果作为只读外部参照，不在 design split 重新选择。
- 检查当前 Path C 是否能以同一学习规则产生多个独立策略，并参与双方位置交换后的 XP；当前“固定 ego 对自建 partner registry”的协议不能直接冒充标准 XP。
- 完成标准：形成一份可由现有 `EXPERIMENT_PLAN.md` 与预注册模板共同表达的标准协议；不新增独立门控文件。

### B1：标准协议接线检查

- 在 `test_time_simple` 上运行极小 Type-A smoke，只检查环境、观察、动作、循环状态、双方位置交换、回报记录和 XP 聚合是否接通。
- smoke 数字不得进入论文表格，也不得用于判断方法优劣。
- 不训练任何已发表基线。

### B2：匹配训练主方法和必要对照

- 构造 10 个完全独立的外层训练单元；各单元不与其他单元共享策略权重、随机数或配对经验。
- 从每个单元的同一合格骨干复制并独立训练决策导向探查、通用回应信息探查、随机安全探查和无探查四个条件；适应前骨干另作零训练成本参照。
- 新布局正式训练预算与 ICLR 2025 主设置对齐为每 seed `30,000,000` 个环境步；实际 episode 与 transition 数必须从产物回读。
- 保存每个匹配条件的 checkpoint、结构、配置、训练曲线和有效数据预算。无需为自建 RNN/HMM/particle 系统生成主表 checkpoint，也不重新训练已发表基线。
- 晚期训练表现仍在上升时，不提前读取主结论。

### B3：公开协议主评估与冻结外部验证

- `test_time_simple` 只读取决策导向探查相对无探查的确认性主终点；方法、阈值和统计代码冻结后，再依次评估 `test_time_wide`、held-out 伙伴族和 Hanabi 的 H3 端点。
- 每个布局使用 10 个独立 seed 的全部 XP 配对，每个配对 500 个 episode，并纳入双方角色交换。
- 主表并列：Path C、Self-Play、State-Augmented、Other-Play、FCP 的已发表 XP；SP 和 gap 同时给出。
- 不在运行后改布局、伙伴定义或指标。

### B4：消融与机制

- 在 Path C 主 checkpoint 上运行 value-directed、random probe、no probe、禁用 residualization 和必要的记忆删除比较。
- full-history recurrent network、exact belief filter、hidden Markov model belief filter 和
  particle belief filter 如需保留，只作为内部消融或机制上界，不再标作已发表主对照。
- 扣除探针成本后的预算曲线、信念平均干预分布、合成正例、null 与指纹泄漏均在此阶段解释；它们不阻止 B3 的标准性能评估。

### B5：可选的多 episode 伙伴适应扩展

- 只有在完整采用 ICRL4AHT 的公开测试 manifest、100-episode 协议和聚合方式时才运行。
- AD、DPT 与 random 的 ICML 2026 数字单列，不能与 ICLR 2025 XP 数字混合排序。
- 本块不延迟 B3。

## 9. M0 静态差距核查结果与修订方案（R005，2026-07-11）

本节是纯静态代码核查的结果：三路并行扫描（评估器；训练与策略接口；环境与官方协议参照），
所有关键结论的行号已人工复核；未运行任何代码。官方侧证据来自 jaxmarl v0.1.0 源码
（GitHub tag）、官方实验仓库的 env 配置 yaml 与评估脚本（只读网络访问）。

### 9.1 总判定

加载 `test_time_simple`/`test_time_wide` 布局不是阻塞：两布局都在 jaxmarl v0.1.0 布局
注册表中，且 R003 已证明适配器能对全部 22 个双智能体布局完成 reset。真正的阻塞是六项
协议语义差距（下表）。其中环境参数只有一个需要改代码；其余五项是结构性的：现有
"option/CE 图/96 维特征器/脚本伙伴"栈以全局特权状态为前提，不可能以补丁方式满足官方
局部观测协议。修订方向是为标准基准建一条并行的原语动作路径，而不是改造旧栈。

### 9.2 差距清单（静态事实，带出处）

1. **环境适配层 `OCV2Adapter`（最小差距）。** 构造函数缺 `indicate_successful_delivery`
   透传（`env_adapter.py:66-90`）；该参数在 jaxmarl v0.1.0 `OvercookedV2.__init__` 中
   真实存在、默认 False，官方 Test Time 配置设为 True。这是唯一必须改适配器代码的环境
   参数。其余官方参数（`agent_view_size=2`、`random_agent_positions=True`、
   `max_steps=400`、布局名）适配器均可透传，只缺配置：现有全部 config 只写
   `asymm_advantages`/`cramped_room`，从不设置 `agent_view_size`（等于完全可观测），
   `random_agent_positions` 全为 False，训练侧 `_build_env` 的 `max_steps` 默认 200
   （`train_aris.py:1036-1053`）。另外 `force_path_planning` 官方不设置（环境默认
   False），而现 asymm 配置与适配器默认为 True——这是环境动力学差异，标准路径必须显式
   置 False。适配器 `step(ego_action, partner_action)` 把 ego 位置写死为 `agent_0`
   （`env_adapter.py:133,180-183`）。
2. **观测与证据（最深的科学差距）。** 96 维特征器是全局特权观测：全图 shortest-path
   距离（`obs_featurizer.py:191-230,296-309`）、对方完整特征块（`:41-63`）、直接读
   `state.recipe`（`:311-314`）。官方协议在 `agent_view_size=2` 的局部窗口 DEFAULT
   观测下运行，"走到配方指示牌读出配方、再用行为传达给同伴"正是 Test Time 布局要测的
   协调现象。特权观测同时"多给"（全局状态）与"少给"（没有配方指示牌相关特征），两个
   方向都破坏与已发表数字的可比性。证据行 schema 还包含 `partner_primitive_actions`
   与由全局状态推导的 progress events（`path_c_sequence.py:133-144`），在局部观测下
   不可观测。
3. **动作空间。** 受训策略在 CE 图导出的 option 上决策（每布局 26–28 个），option 的
   原语展开靠读完整模拟器状态做路径规划（`option_executor.py:56`）；官方协议的策略在
   6 个原语动作上、只依据自身局部观测行动。option 层本身就是特权组件。
4. **策略训练接口。** 训练是"单个受训主策略（固定 agent_0）对脚本伙伴（agent_1）"
   （`train_aris.py:1069-1094`；`partner_pool.py:927`），优化器只含一个 q_net
   （`train_aris.py:495-505`）；脚本伙伴忽略自身观测、直接读特权状态
   （`partner_pool.py:772` 的 `del obs_partner`）。不存在自博弈（同一策略驱动双方）或
   双方受训。各 seed 共享同一 `graph.json`、CE 矩阵、replay、伙伴注册表与 split
   manifest（`train_aris.py:1133-1146`），违背"10 个完全独立训练运行"。预算以梯度更新
   计（5k–40k，约 ≤2000 局 ≈ ≤0.8M 环境步），没有环境步计数，也没有 30M 步的配置
   路径——官方单 run 预算 3e7 环境步约为现有最大运行的 37 倍。
5. **角色交换。** ego=agent_0 在适配器、option 执行器（`option_executor.py:56-58,67`）
   和训练器约 8 处写死；仓库全局搜索 cross-play/self-play 零命中；不存在任何位置交换
   代码。
6. **评估器与 XP 聚合。** 评估循环是"graph 变体 × 注册表脚本伙伴名"
   （`evaluate_aris.py:879-881`），伙伴名必须在 `PARTNER_REGISTRIES`（`:4048`）；没有
   checkpoint 对 checkpoint、没有 SP、没有 seed×seed 配对矩阵。动作选择是 option 级
   贪心 argmax（`:3100`）。记录的回报是重塑后的训练回报：按贡献重记账的稀疏奖励
   （`sparse_credit.py` 的 contrib_team 分支）加塑形项、再减每步成本与探针成本
   （`evaluate_aris.py:2655,2829`）；官方指标是 400 步内 `rewards["agent_0"]` 的原始
   和。聚合是"对脚本伙伴取均值"，不是"对 90 个有向配对取均值±标准差"。形式评估另有
   硬门 `_enforce_reward_scale`（`:4427`）把评估绑在 CE 图目标 × partner_set 上。
   吞吐上，评估是单环境逐步 host 同步循环（`env_adapter.py:192`）；已有的批量路径
   `BatchedEnvPool`（`batched_rollout.py:83`）目前只被 CE 采样使用。每布局标准评估
   规模 = 100 个配对 × 500 局 × 400 步 = 2000 万环境步。

### 9.3 修订方案（最小改动范围，按实施对象）

总述：为标准基准新建一条"官方局部观测 → 循环 TD 价值网络 → 原语动作"的并行路径。
训练伙伴用 seed 内自博弈池（与 Fictitious Co-Play 同类的伙伴形成方式，但整个系统仍
只有 TD 价值损失）；评估用配对矩阵驱动器直接产出官方口径的 SP/XP。现有 option/CE/
特征器/脚本伙伴栈整体保留为机制仪器线与消融，不再承担主表。

1. **`OCV2Adapter`（改现有文件，改动很小）。** 加 `indicate_successful_delivery:
   bool = False` 透传；补一个槽位中性的双动作步进约定（按 `{"agent_0": a0,
   "agent_1": a1}` 传入，不再语义上区分"我方/伙伴"）；新增 `test_time_simple` 与
   `test_time_wide` 两份标准环境配置：官方 kwargs（`agent_view_size=2`、
   `negative_rewards=True`、`random_agent_positions=True`、
   `sample_recipe_on_delivery=True`、`indicate_successful_delivery=True`）加
   `max_steps=400`、`observation_type=default`、`force_path_planning=False`、
   `random_reset=False`。
2. **标准观测编码器（新增）。** 消费 DEFAULT 局部窗口网格观测（每个 agent 以自我为
   中心的 5×5×通道窗口）加自身上一动作与上一步回报；小卷积网络编码后接现有
   `RecurrentEnsembleQ` 的 GRU 集成头（复用 `path_c_sequence.py` 网络，只换编码
   前端）。循环隐藏状态必须逐步携带：现在每次决策把整段证据重放一遍，400 步原语决策
   下是平方级开销。证据 schema 出一个基准版：只含自身可观测量（自身观测窗口、自身
   动作、回报、终止标志），移除 `partner_primitive_actions` 与全局 progress events；
   identity/mechanism/style 字段照旧禁止。
3. **策略训练接口。** 已实现的标准路径先训练参数共享的自博弈策略，再以单一时序差分损失
   和归一化 advantage 分歧探针对 seed 内快照池训练。该实现保留为历史消融，不再代表提案
   主方法。当前主方法先形成合格循环骨干，再从同一骨干复制四个匹配适应条件；决策导向条件
   另训练伙伴回应模型、伙伴条件价值头和 `J_use−V_mask` 控制器。系统整体不是单一损失，
   但共享骨干只接收 critic 的时序差分价值梯度。跨外层训练单元零共享；环境步、episode、
   transition 和 GPU 时间全部从产物回读。seed 内快照只能提供同一伙伴族内的原型，不能
   冒充跨伙伴族支持或 held-out 证据。
4. **角色交换。** 由配对驱动器完成：有向配对 (i, j) 即 i 的策略占 agent_0、j 的策略占
   agent_1；90 个有向配对天然覆盖双方位置（官方评估脚本用 permutations 的同一做法）。
   观测以自我为中心、`random_agent_positions=True`、参数共享自博弈三者共同使策略
   天然与位置无关，网络侧不需要额外改动。
5. **标准评估器与 XP 聚合器（新增模块，与 `evaluate_aris.py` 解耦）。** 加载 10 个
   最终 checkpoint（不按测试回报挑选）；配对集 = 10 个 SP（同一 checkpoint 占双方）
   加 90 个有向 XP；每配对 500 局、每局 400 步；每局原始回报 = 各步
   `rewards["agent_0"]` 之和（负回报保留）；行级持久化（布局、i、j、局号、随机种子、
   回报）；汇总从原始行重算：XP 均值±标准差按 90 个配对、SP 按 10 个 run、gap 并报，
   另按训练单元节点重采样计算 95% 置信区间（§3.2 已定）。行动规则是方法自身冻结的
   规则（对集成均值 Q 贪心加预注册探针规则），SP/XP 同一规则、不做每布局调参；官方
   基线从其随机策略分布采样，本方法的确定性行动规则属于方法定义的一部分，须在预注册
   中写明，episode 间随机性来自 `random_agent_positions` 与配方抽样。该路径不接
   `_enforce_reward_scale`、伙伴注册表与 design ledger。
6. **明确保留不动。** `asymm_advantages` 上的 option/CE/96 维特征器/脚本伙伴注册表/
   belief-kernel 审计整套保留，作为机制主张 C3 与消融的仪器线；该线的任何数字不进
   主表。

## 10. R020 正式训练配置冻结（2026-07-12）

远端证据重绑定（提交 `c70bf03`，63 项回归与 R010 级 smoke 全部通过）之后，本节把
R020 的全部数字槽一次冻结。冻结载体是两份配置文件：
`experiments/overcooked_v2/configs/path_c_standard_formal_simple.yaml`（观测 5×5×39）与
`path_c_standard_formal_wide.yaml`（观测 5×5×43）。授权时只允许按基准文件冲压逐 seed
副本（simple 用 101–110，wide 用 201–210），除 seed 与输出目录外任何字段变更都要求
重新冻结并记录。

### 10.1 冻结值与理由

1. **预算与两阶段划分：** 每 seed 总计 30,000,000 环境步，其中自博弈伙伴池阶段
   10,000,000 步、Path C 主策略阶段 20,000,000 步。两阶段都计入总预算，因此每 seed
   总步数不超过官方单 run 的 3e7 口径（Fictitious Co-Play 的公开数字还不含其伙伴池的
   训练成本，我们的口径严格更省）；交付策略拿走三分之二预算。
2. **伙伴池快照日程：** 自博弈阶段的 25%、50%、75%、100% 四个等距快照
   （2.5M/5M/7.5M/10M 步），提供从中等到成熟的技能多样性，对应 Fictitious Co-Play
   用多阶段 checkpoint 构池的做法；池内前向已按指派行子批执行，池大小不再放大伙伴
   推理成本。
3. **主策略初始化：** 从零初始化（`fresh`）。从自博弈终点热启动会先锁死单一约定，
   与"跨博弈失败源于约定锁死"这一基准现象直接冲突；从零对池训练与 Fictitious
   Co-Play 的伙伴形成同类，使 FCP 成为"同类伙伴形成、差一个价值导向探针"的干净
   主对照。
4. **探针参数：** 开启，分歧阈值 0.02（统计为 variance，回报下限 0.0）。分歧统计非负，
   阈值必须严格为正，失效关闭校验已在配置层与机制层双重生效；0.02 沿用既有预注册
   约定，阈值敏感性由 R040 消融回答，不在主运行前调参。
5. **向量化与整除：** 批量 250 个并行环境。250 整除全部阶段预算与快照边界（256 不
   整除 3e7），评估阶段 500 局也能被 250 整除，全程保持固定的 XLA 批形状。
6. **优化器与回放：** 学习率 2.5e-4（官方 IPPO 同值）、gamma 0.99、目标网络每
   100,000 环境步同步、每个向量步 1 次梯度更新（全程约 12 万次更新）、回放容量
   1024 个完整 episode、小批 8 个 episode、经验起点 128 个 episode、探索率 1.0 线性
   降至 0.05（每阶段前 2,500,000 步）、集成头 5 个、bootstrap 概率 0.5、固定先验
   缩放 0.1。这些是价值方法的常规量级，不做运行前调参；训练稳定性由 R020 第一阶段
   的读数检验。
7. **模型容量：** 视觉嵌入、编码器与循环维度均 128，与官方基线的 128 维 GRU 同
   容量级；卷积通道 [32,32,16]。

### 10.2 数据充分性预核

按冻结值推算：主策略阶段每 seed 20,000,000 步 ÷ 400 步/局 = 50,000 个联合 episode，
自博弈阶段 25,000 个，远高于项目内部 ≥2000 局的读数下限。正式读数仍须在运行后从
manifest 的实际计数回读确认，推算值不能替代回读。

### 10.5 seed 101 诊断运行设计（预注册，运行前冻结判读）

目的：区分"最终模型只是不与自身协调"与"对训练伙伴也没有任务能力"，并检查自博弈
阶段本身是否产生了任务能力。配对集合共 9 项、每项 500 局、每局 400 步（约 180 万
评估环境步）：

1. 最终模型 × 四个伙伴快照的全部有向配对（8 项，覆盖双方位置）；
2. 最终自博弈快照（第 1000 万步）与自身配对（1 项）——它回答"自博弈阶段在 1000 万
   步时是否已能完成配送"，把"主策略没学会"与"伙伴池本身无能力"分开。

附加遥测：诊断评估在探针开启路径下额外记录每步最大分歧统计的分位数分布（按配对
汇总）。500 局自博弈中探针为 0 只有两种解释——集成头处处一致，或 0.02 阈值高于
真实分歧范围；该分布把两者分开，并为 R040 的阈值敏感性消融提供实测标定。

判读规则（运行前冻结，禁止事后重解释；只约束解释，不预排后续动作）：

- 若最终模型对快照的双位置回报显著大于 0 而自博弈配对为 0，读作"自博弈约定不
  匹配"：能力存在，主表的 SP 读数问题另行处理。
- 若包括快照自配在内全部约为 0，读作"自博弈阶段在 1000 万步内未达到任务能力"，
  问题先于 Path C 主张本身。
- 若快照自配大于 0 而最终模型对快照约为 0，读作"主策略阶段未能从有能力的伙伴池
  学到任务能力"。

实现前提：现有校准评估只接受正式最终 checkpoint 作为策略；诊断运行需要一个
`diagnostic` 评估类别，允许伙伴快照按其 manifest 哈希作为配对策略载入，
`scientific_readout_allowed` 恒为 false，汇总只给每配对的均值、标准差、极值与零回报
比例，不做自举。该类别实现与运行都尚未授权启动。

### 10.6 seed 101 全零的静态机制分析与冻结修订二（已实现，seed 101 重训已授权）

§10.5 的诊断运行不再是当前最高价值步骤：代码已确认训练信号与网络结构存在两项缺陷。
旧训练没有逐步回报记录，因此下列第一项是最强机制解释，不是对历史 30M 步奖励序列的
直接观测。三层问题按因果顺序如下：

1. **主因候选：训练遗漏环境原生塑形回报。** 标准训练器只把原始稀疏团队奖励喂给时序差分
   目标（`path_c_standard_training.py` 中 `shared_team_reward`），并丢弃环境返回的
   info；而官方基线的训练奖励是"原始 + 退火系数 × 逐 agent 塑形奖励"
   （官方 `ippo_rnn_overcooked_v2.py:355-357` 直接读 `info["shaped_reward"]`，
   `REW_SHAPING_HORIZON=1.5e7`，即 30M 步预算的前一半线性退火到 0），报表仍只报
   原始回报。在 `test_time_simple` 上，一次正确配送要求"取洋葱×3 → 入锅 → 等待烹饪
   → 取盘 → 盛汤 → 走到出餐口 → 配方匹配才交付"，随机探索在 400 步内完成整链的
   概率很低，且错误交付还会被负奖励惩罚。旧训练没有保存逐步奖励，不能直接断言 30M
   步训练信号恒零或价值函数必然收敛为常数。已有产物与该机制相容：最终 checkpoint 的
   advantage 头 RMS 为 0.031、最大绝对值为 0.13；主策略阶段共记录 2,364 次探针；校准
   500 局回报与探针全为 0。探针还受候选价值下限约束，低探针数不能只归因于分歧低。
   “把'报告原始回报'误当成
   '必须用原始奖励训练'"是本项目在 §10 冻结时的判断错误：可比性只约束评估口径，
   不约束训练信号。
2. **结构缺陷：观测编码器在投影前做全局平均池化**（`path_c_standard.py` 的
   `LocalObservationEncoder`，卷积栈以 `AdaptiveAvgPool2d((1,1))` 结束）。5×5 自我
   中心窗口内"锅在左还是在右"的方向信息被大幅压缩（边缘填充仍可能保留少量位置
   痕迹），而官方 CNN 保留展平的空间图。这会明显妨碍方向敏感的导航表示。
3. **次级：探索日程在无信号的价值上过早收敛。** 每阶段 250 万步把探索率降到 0.05，
   之后约 87% 的预算在近贪心地采集退化数据。在主因修复后该项只需温和放宽。

价值方法本身（单时序差分损失）按方法身份保留：官方基线用的是 PPO，这是已记录的
风险项，但在塑形信号与空间编码修复后，循环 Q 学习没有先验不可行性；新加的逐窗口
指标会直接给出判据。

**冻结修订二（内容）：**

- 训练奖励改为"原始 + β(t) × 逐位置塑形奖励"，β 在每阶段前 50%（自博弈 500 万步、
  主策略 1000 万步）线性退火到 0，镜像官方 15M/30M 比例；塑形奖励用环境自带的
  `info["shaped_reward"]`（逐 agent），评估与所有报告口径不变，仍只用原始回报。
  **喂给循环网络的"上一步奖励"输入在训练与评估都保持原始通道**，避免训练（塑形）
  与评估（原始）之间的输入分布漂移；塑形只进入时序差分目标。
- 观测编码器去掉全局平均池化，改为空间展平后线性投影（5×5×16=400 → 128），保留
  LayerNorm；参数量增加可忽略。
- 探索率退火期从每阶段 250 万步放宽到 500 万步，下限 0.05 不变。
- 指标行增加：逐窗口配送事件计数（原始奖励>0 的步数）、负原始回报事件计数、
  塑形奖励和、退火系数、以及探针分歧统计的窗口分位数（为阈值 0.02 提供实测标定；
  并分别记录分歧阈值与候选价值下限通过率）。负原始回报不能直接等同错误交付，因为
  配方提示按钮也有原始回报成本。
- 运行方式：修订实现 + 远端针对性回归与 smoke 重验证后，重训 seed 101（新输出目录，
  旧产物不覆盖不删除）。预注册一条停机规则：主策略阶段前 500 万步的配送事件计数
  若恒为 0，停止运行并复盘，不烧完剩余预算。
- 本修订推翻 §10.1 第 6 条"训练稳定性由第一阶段读数检验"之外的任何提前宣称；
  两批启动设计本身按预期工作——4.14 GPU 小时暴露了整条信号链问题，代价可控。

执行状态：修订代码已实现，旧 checkpoint 兼容读取测试已加入；远端 CUDA JAX 定向回归
70 项通过，R010 已重新完成两 seed 训练与 8 行评估。用户已授权 seed 101 在新输出目录
正式重训；旧 checkpoint 与旧校准产物均不覆盖。重训已以退出码 0 完成全部 30M 步：
训练奖励通道确认非空，主策略到 5M 步有 26 个正原始事件，因此没有触发停止规则；但最后
5M 步的正、负原始事件和窗口平均原始 episode return 都为 0。该读数否定“奖励通道修好即
足以恢复任务能力”的推断。当时记录的后续动作是对新最终 checkpoint 执行与旧模型完全
相同的 500 局最小原始回报校准；该动作已归档，不再表示当前执行顺序。

### 10.7 修订二后仍全零的第二层根因：交付行为灭绝（静态解剖，2026-07-12）

实现核验：塑形通道、逐位置分配、退火日程、双通道存储（训练目标含塑形、网络输入
保持原始）全部按冻结实现，无实现缺陷。失败在设计层，机制是**行为灭绝**而不再是
信号饥饿：

1. **价值贪心控制没有行为惯性。** 策略 = 对 Q 取 argmax，而 Q 被持续重拟合到当前
   回放的目标上。塑形系数退火到 0 后，回放里几乎没有交付事件，目标全面回到约 0，
   支撑"去交付"的 Q 排序随之瓦解——12,500 个末期 episode 连一次交付尝试都没有
   （正负事件均为 0）。官方 PPO 是同策略方法：行为存在参数里，没有梯度就不退化；
   而且官方策略在退火结束前已经每局交付约 7 次，原始 +20 信号自身足以维持最优。
   我们的峰值交付率只有约 0.2%（前 500 万步 26 次），远未到"原始信号自持"的逃逸
   速度，拐杖一撤行为就灭绝。
2. **回放遗忘。** 容量 1024 个 episode（约 41 万步）只覆盖阶段的 2%，先进先出；
   一个交付 episode 在缓冲里只活约 50 万步。全阶段仅 92 次交付，末期缓冲几乎必然
   不含任何交付经验——没有任何东西维持交付路径上的价值。
3. **1 步时序差分在约 80–120 步的交付链上传播信用太慢。** 终端 +20 的信用每次更新
   只回传一步，且读配方指示牌这一关键子任务没有任何塑形，错误交付还被负奖励惩罚
   ——确定性贪心一旦把"在出餐口交互"排成负值，就会同时剪掉错误与正确交付。官方
   用 GAE(λ=0.95) 等效多步信用。
4. **两阶段课程倒置。** Fictitious Co-Play 的池成员是完整训练的策略（每个池成员
   3e7 步，池成本不计入其报表口径）；我们为了"总预算 ≤ 官方单 run"的表述把池阶段
   压到 1000 万步（塑形 500 万步就撤），产出每 230 局才交付一次的伙伴，再让从零
   初始化的主策略对着这批不会做饭的冻结伙伴学 2000 万步。这是 §10.1 预算划分决策
   的直接后果。

**结论：** Path C 方法本身（探针、伙伴抽象、只用时序差分训练表示）尚未被检验——
它连一个会做饭的基础策略都还没拿到。当前被证伪的是"用 1 步时序差分、小回放、
贪心控制的价值学习栈 + 两阶段 10M/20M 预算，在该基准上获得基础能力"这套配方。

**当时建议的决定性实验（已归档）——30M 单阶段自博弈能力探针：** 去掉全部池/
主策略结构，只问"这套只用时序差分的学习器到底能不能在 `test_time_simple` 学会
交付"。学习器修正（冻结修订三草案）：n 步时序差分目标（n=5）、回放容量 8192 个
episode、塑形退火改为 1→0.1 后保持（训练信号口径是方法内部事务，评估口径不变，
与官方数字的可比性由"只报原始回报"保证；措辞降级在论文限制段说明）、训练期探索
下限提高到 0.1。逐窗口交付事件曲线直接给出"逃逸速度"读数。约 4.4 GPU 小时。

**并行待裁决的方法分叉（用户决定，不阻塞探针）：** 若探针仍无法获得基础能力，
备选是"表示纯时序差分的 actor-critic"——循环主干只接受 critic 的时序差分梯度
（保住论文命题"表示只用价值梯度训练"），浅 actor 头在截断梯度的特征上做策略梯度。
这改变"全系统单一 TD 损失"的不变式措辞，属于方法治理决定，须另行预注册。

### 10.8 外部评审裁决（2026-07-12）

对用户提供的外部深度评审逐项核验后的裁决：

**证实并采纳（四项）：**
1. 探针量纲错误（评审 §四）：集成头分歧度量的是参数/数据不确定性，不是伙伴机制后验
   不确定性；同一批零回报轨迹会让各头一致收敛，于是"伙伴歧义最高时探针自动关闭"。
   这是冻结探针机制本身的方法级缺陷，不只是本次坍缩的症状。其静态测算（仅固定先验
   时分歧中位数约 2.6e-4，远低于 0.02 阈值）与我们观察到的零探针一致。
2. `return_floor` 绝对 Q 门（评审 §五）：已在当前代码证实（`candidate_q >= 0.0`）。
   Q 加常数不改变任何决策相关量，却翻转该门——确定性的不变性缺陷，属于冻结的探针
   安全规则设计错误。修复：改为相对 greedy 的 regret 上限加显式预算。
3. 伙伴池没有能力准入门（评审 §七）：与我们的课程倒置结论一致，且"按训练步数即认定
   为有效伙伴"确属流程缺陷。
4. 环境信息成本事实（评审 §一）：已从源码证实 `INDICATOR_ACTIVATION_COST=5`
   （overcooked.py:1347 直接从原始 reward 扣除）——读配方这一信息动作本身付 −5。
   末 500 万步零负事件因此还意味着从未读过配方。事件统计应改为记录环境显式交付/
   指示牌事件旗标，而非"净 step reward 符号"。

**证伪或需更正（三项）：**
1. 评审 §六称"运行在 500 万步被停止、末期即前四分之一"——错误。停止规则未触发
   （前 500 万步有 26 个正事件），全程 30M 步、300 行指标完整跑完。更正后结论更强：
   探索退火结束后又训练了 1500 万步，行为仍然灭绝。
2. "包内测试为 0"——评审的上传包缺 tests 目录；仓库有 70 项远端通过的针对性回归。
3. "严重偏离提案"的归因需要修正：证据合同收窄与分歧探针是 §9 迁移时的**有记录冻结
   决定**（部分由官方局部观测协议强制），不是无声实现漂移。真正成立的批评是：迁移
   时原样移植了探针机制，没有重新推导它在新基底上是否还能表达伙伴不确定性——这一
   步是我们的设计遗漏，评审 §四 把它说清楚了。另：逐位置塑形与官方配方一致（官方
   也按 agent 加各自塑形），其批评力仅限于"伙伴冻结不学习"的第二阶段。

**治理张力（评审 P0 第 5 条不可直接采纳）：** 响应模型 + 信息价值探针违反冻结不变式
（单一时序差分损失；无互信息目标；探针=预注册的归一化 advantage 分歧）。采纳即方法
重设计，须用户裁决并重新预注册。评审 P0 第 3 条（把 Path C 定位为"任务胜任骨干之上
的适应层"）与论文命题兼容且是当前最强的架构候选——残差伙伴抽象本就预设任务胜任。

**并入修订三草案的静态修复：** 相对 regret 探针安全门与显式预算；Q 平移不变性测试；
零回报 Bellman 固定点测试；环境显式事件旗标进指标行；伙伴池能力准入门实现。
在当时的评审顺序中，基础能力探针（30M 单阶段自博弈）排在下一位；该顺序已由当前
[PATH_C_EXECUTION_PLAN.md](PATH_C_EXECUTION_PLAN.md) 取代。评审的 2×2 隔离实验在探针几乎
从不触发的现状下信息量有限，留待基础能力建立后再议。
