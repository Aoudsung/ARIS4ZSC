# Path C 研究工作流

**生效日期：** 2026-07-29。本文档取代旧的逐版本修复循环，是判断"下一步做什么"的唯一流程依据。

## 一、旧工作流的四个失败模式（有记录依据）

1. **方法先于现象。** V4 到 V4.4 共五轮机制修复，每轮工程上都正确，任务效应
   0→0→0→−0.08→0。真正回答"这个基底上有没有可捕获的伙伴价值"的官方策略库交叉
   矩阵只花 320 万只读环境步，却在五个版本和一次 1.01 亿步审计之后才执行。测量
   现象存在性的成本是修复循环的百分之一，但被排在了最后。
2. **修复循环没有停机判据。** 每轮修复都由上一轮的诊断驱动，诊断永远能找到下一个
   可修的机制，于是循环自我延续。缺失的不是诊断能力，而是一条事先写死的"连续 N 轮
   任务效应为零即停机、退回现象测量"的规则。
3. **文档只进不出，然后一次性清仓。** 治理与记录持续增厚（594 行开发诊断报告、
   上千行 METHOD_LOCK），2026-07-29 一次提交删除 1.2 万行，顺带删掉了项目仪表盘
   仍在链接的两份现役证据报告，入口文档指向不存在的文件。囤积与清仓是同一个病的
   两个相位：没有"何时退休、退休到哪"的常规动作。
4. **证据仪式与证据价值错配。** `scientific_readout_allowed: false` 的开发诊断
   配了完整 SHA-256 哈希表和独立重算，次日即被整体删除；哈希仪式该花在承载主张的
   读数上，而不是按报告体裁一律套用。

## 二、流水线：五个阶段

每个阶段有一个入口问题、一个最便宜的判定测量、一个明确的通过/停机判据。禁止跳级；
禁止在下游阶段返工上游问题超过一次而不退级。

### 阶段 0 —— 问题陈述

- **产出：** 一页纸，一个可证伪问题，及"用什么测量、多大效应算存在"。
- **判据：** 问题写不成单一可证伪句子的，不进入阶段 1。

### 阶段 1 —— 现象存在性测量

- **入口问题：** 这个基底上，目标现象是否存在、量级多大、上限在哪？
- **规则：** 优先只读、优先复用已有数据和 checkpoint；仪器不含任何待研究的学习
  组件（D1 纪律：仪器先于方法）。
- **判据：** 测得的可捕获上限低于最小值得追求的效应量 → 换基底或收缩主张，
  不进入阶段 2。上限充分 → 该数字冻结为后续所有版本的天花板参照。

### 阶段 2 —— 工程化阳性对照

- **入口问题：** 用手工组装（已有策略、查表、监督信号）能吃到上限的多少？
- **定位：** 它不是论文贡献，是天花板的构造性证明和后续涌现方法的教师/标尺。
- **判据：** 阳性对照吃不到上限的一半 → 说明缺的是可识别性等基底条件，回到
  阶段 1 重新测量；吃得到 → 差距数字冻结，进入阶段 3。

### 阶段 3 —— 研究级方法

- **入口问题：** 目标能力能否按北极星要求（涌现、不手设结构）达到阳性对照水平？
- **停机判据（事先写死）：** 连续两轮修订的任务效应相对阳性对照无改善 → 停机，
  裁决在"方法主张收缩"与"退回阶段 1/2"之间做出，不允许第三轮同类修订。
- **每轮修订必须预登记：** 修的是什么机制、预期在哪个读数上出现多大变化、
  读数不变时的结论是什么。读数不变时不得当场改口为"还需要修下一个机制"。

### 阶段 4 —— 确认性冻结与正式运行

- 方法、阈值、统计代码全部冻结后进入正式多单元训练；此阶段规则沿用现有
  数据充分性与预登记纪律，不在本文档重复。

## 三、文档三层制

1. **PROJECT_DASHBOARD.md（活文档）：** 上限 150 行；只写当前阶段、当前判据状态、
   唯一下一步；所有链接必须可解析——增删文件的同一提交内修链接。
2. **FINDINGS_LEDGER.md（只追加台账）：** 每个已裁决结论一段话：日期、结论、
   证据指针（commit 或远端路径）。结论被推翻时追加新条目，不改旧条目。删除任何
   状态报告前，其结论必须已入台账。
3. **单次运行报告：** 开发诊断上限一页，不配哈希表；哈希表、独立重算、完整口径
   章节只给承载主张（`scientific_readout_allowed: true`）或作为裁决依据的运行。

**退休规则：** 文档退休 = 移入 `archive/` + 台账留一行指针，随取代它的提交同时
发生；禁止累积后成批清仓。
