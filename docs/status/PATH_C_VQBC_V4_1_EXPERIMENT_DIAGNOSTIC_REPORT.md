# Path C VQBC V4.1 当前实验运行与问题诊断报告

**日期：** 2026-07-26
**对象：** 价值商信念条件 Bellman 控制器（Value-Quotient Belief-Conditioned Bellman
Controller，VQBC）V4.1
**运行类别：** 开发诊断，不具备科学结论权限
**状态：** 首开发单元的训练、四模式评估、回应屏蔽对照和控制路径追踪均已完成；十单元正式
训练继续关闭

## 技术摘要

V4.1 已经修复第四版最直接的结构失败：八个潜在槽不再保持完全相同，最近一批完整回合中的
12,800 个状态全部形成 8 个活动价值商，回应后验也会改变正常动作。这个结果说明独立专家、
完整回合责任度和持久槽后验已经产生作用。

但当前方法仍未实现方案要求的“预测回应价值由真实后续控制承载”。500 个回应屏蔽回合的预测
信息净值均明显为正，使用回应和屏蔽回应的最终回报却逐行相同。后续控制路径追踪排除了回应码
恒定、Bayes 更新无效和屏蔽开关空接线：实际回应使使用分支和屏蔽分支的槽信念出现明显差异，
完整回合中也有少量动作轨迹分开。

当前的主要问题是内部评分和真实执行不一致。`J_use/J_mask` 使用无约束的下一动作最大值，假定
观察回应后可以直接选择预测最优动作；实际执行分布却受到冻结参考策略和
Kullback–Leibler 散度（KL 散度）温度约束。追踪中，回应更新使下一步 `J_use` 的最大绝对变化
均值达到 2.364，真实动作分布的总变差距离均值却只有 0.000741，32 个样本的下一步动作全部
相同。换言之，模型预测的是一个执行器通常不会实施的控制切换。

因此当前不应继续增加训练预算。下一次代码修订应优先让回应价值的延续算子与真实 KL 约束
执行分布完全一致，再重复同一个开发单元。

## 1. 本报告回答的问题

本报告用于回答三个开发决策问题：

1. V4.1 是否打破了第四版的潜在槽对称性？
2. 回应后验是否进入了真实的正常动作路径？
3. 为什么预测信息净值明显为正，而回应屏蔽没有产生回报效应？

分析对象只包括 Test Time Simple 的 seed-100 单 checkpoint 开发运行。这里的自我配对
（self-play）是同一个 checkpoint 的两侧协作，不是十个独立训练单元之间的跨策略配对。

这里使用精确表格而不是趋势图，因为证据来自一个训练单元和离散控制层；绘制时间趋势会暗示

的科学证据。

## 4. 潜在槽已经分化，但识别仍集中在少数专家

第四版首开发单元的责任度熵始终为 `log(8)`，所有状态只有一个活动价值商。V4.1 的对应结果
发生了明确变化：

- 最终责任度能量间隔均值为 1103.261，第 5 和第 95 百分位数为 529.204 和 1656.389；
- 最近一批完整回合的 12,800 个状态全部形成 8 个活动价值商；
- 最终后验熵均值为 0.080809，而不是均匀八槽的 `log(8)`；
- 最后一个观测中实际使用 12 个非终止回应码，困惑度为 5.93487；15 个码本目标码全部使用，
  困惑度为 12.9743。

不过“八槽都可区分”不等于“八槽都得到有效训练”。最终 32 个训练回合的每槽有效质量为：

```text
[0, 4, 23, 1, 0, 3, 0, 1]
```

对应有效槽数只有 2.549。三个槽在该窗口完全没有质量，主要槽独占 23/32。当前状态应描述为
“潜在槽已分化，但责任度使用集中”，不能描述为八个稳定且均衡的伙伴控制假设。

这个问题不是本轮回应屏蔽零效应的第一根因，因为后验和动作值已经能够产生明显差异；但它会
降低不同训练单元之间的可重复性，并放大结果模型由少数专家决定的风险。

## 5. 后验会改变普通行为，但没有显示收益

四种部署模式使用相同的 500 个回合 seed：

| 部署模式 | 平均回报 | 平均信念熵 | 平均参考动作偏离数 | 解释 |
|---|---:|---:|---:|---|
| `posterior_use` | 168.92 | 0.166305 | 224.398 | 正常更新并使用后验 |
| `prior_only` | 169.04 | 2.07945 | 224.368 | 始终保持均匀槽信念 |
| `reference_only` | 168.84 | 0.166455 | 226.600 | 完全使用冻结参考策略 |
| `generic_response_information` | 168.84 | 0.166455 | 226.602 | 只使用通用回应信息分数 |

`posterior_use` 减 `prior_only` 的匹配平均回报差为 -0.12。500 个匹配回合中：

- 452 个回合的参考动作偏离数不同；
- 376 个回合的回应码计数不同；
- 只有 4 个回合的回报不同，其中 1 个为正、3 个为负。

因此可以确认“后验参与普通行为”，但不能确认“后验改善任务结果”。通用回应信息模式与参考
策略在回报、交付和回应码计数上全部相同，说明当前通用信息分数基本没有越过参考策略偏好。

## 6. 回应屏蔽对照不是接线失败

500 个正式开发对照回合全部在第 0 步触发，预测信息净值范围为 0.139714 至 0.278620，均值
为 0.209274。三个分支的最终回报逐行相同，十个等频分箱和最高分箱中的
`A2-use-A2-mask` 也全部为 0。

仅凭这些原始行，无法区分以下三种情况：回应没有改变后验、后验没有改变动作、动作改变但没有
改变奖励。追加的控制路径追踪已经将它们分开：

1. 回应明显改变后验；
2. 后验对预测动作值影响很大；
3. 下一步真实动作分布几乎不变；
4. 少量完整轨迹最终改变动作，但没有改变奖励。

所以当前失败不是 `mask_response` 参数失效，也不是两个分支错误共享信念。屏蔽确实阻断了触发
动作产生的当前回应；真正的问题是评分所假定的控制能力没有被执行策略实现。

## 7. 主要问题：无约束延续最大化与 KL 约束执行不一致

当前回应使用值包含：

\[
\max_u \sum_m b^{a,y}(m)G_m(z,a,y,u).
\]

这一步假定观察回应后可以无约束地选择动作 `u`。代码位于
`src/path_c/vqbc/policy.py` 的 `bellman_control_values`。

实际执行策略则为：

\[
\pi_{\mathrm{exec}}(u)
\propto
\pi_{\mathrm{ref}}(u)
\exp\!\left(J_{\mathrm{use}}(u)/\alpha\right),
\]

其中 `π_ref` 是冻结参考策略，`α` 是 KL 散度温度。代码位于同一文件的
`regularized_policy`，并由 `src/path_c/vqbc/rollout.py` 的 `policy_action` 实际采样。

这两个对象优化的不是同一个问题。内部最大值只关心哪个预测动作值最高；真实执行还必须克服
参考策略的对数概率差。第 0 步执行分布赋予所采样动作的概率均值为 0.939，说明执行分布非常
集中。结果是内部评分可以报告较高的信息价值，而真实策略仍选择原来的动作。

追踪还显示，大部分后验效应是六个动作共同变化的价值平移：原始 `J_use` 变化均值为 2.364，
扣除共同变化后只剩 0.059。动作无关平移会改变绝对价值，却不会改变归一化动作概率。这说明
回应条件下一动作价值 `G` 的训练目标虽然匹配完整目标 Q 向量，但当前输出主要学到了槽间价值
基线，而不是足以改变动作排序的差异。

### 次要问题：触发分数与被执行动作没有逐行绑定

回应屏蔽运行器用 `max_a S(a)` 决定触发并写入原始行，但两个 A2 分支执行从 `J_use` 分布采样
的动作。32 个追踪样本中，最大信息净值动作始终是动作 1，只有 6 个样本实际执行了该动作。
所有实际动作的 `S(a)` 仍为正，均值为 0.150899，因此这不能解释全部零效应；但用最大值给
实际执行动作分箱会高估该行真正接受的预测回应价值。

## 8. 下一次修订应统一预测算子和执行器

当前最高价值的代码改动不是调低 KL 约束、增加训练步数或改变触发阈值，而是把回应后的延续值
改为与真实执行器一致的 KL 正则化值。对应的基本算子应为：

\[
\mathcal V_{\alpha}(x;\pi_{\mathrm{ref}})
=
\alpha\log\sum_u
\pi_{\mathrm{ref}}(u)
\exp\!\left(x_u/\alpha\right).
\]

它是“期望动作值减 KL 偏离代价”优化问题的值，而不是无约束最大值。回应使用和回应屏蔽必须
把各自的后验动作值送入同一个算子，并使用部署时相同的温度与参考动作分布。

由于当前时刻无法直接知道回应后的下一参考策略分布，结果模型还必须预测回应条件下一参考
分布，或直接预测等价的 KL 正则化延续值。无论选择哪种参数化，训练目标都应由记录转移上的
目标参考策略、目标后验和目标执行分布共同生成，不能继续用无约束 `max_u` 代替。

下一次开发复跑前应静态建立四项一致性：

1. 数学目标中的下一动作分布与运行时真正采样的分布逐元素相同；
2. Bellman 目标、结果模型延续目标和回应信息价值使用同一个目标执行分布；
3. 回应屏蔽原始行同时记录最大 `S(a)` 和实际执行动作的 `S(a)`，分箱只使用后者；
4. 原始行记录触发后信念距离、下一步动作分布距离、首次动作差异和首次奖励差异，使零回报不再
   掩盖差异消失的位置。

这四项属于同一个目标—执行一致性修订，不是四条独立实验路线。

## 9. 复跑验收重点

修订后的同一 seed-100 开发单元首先需要回答一个问题：预测为有价值的实际回应，是否在真实
KL 约束策略中提高改变后续动作的概率，并最终在匹配屏蔽对照中产生非零任务效应。

复跑应继续使用相同训练预算、相同 500 个评估 seed 和相同回应屏蔽 seed，避免同时改变数据量。
需要重点回读：

- 实际执行动作 `S(a)` 与下一步动作分布距离的关系；
- 预测 KL 正则化延续值与真实分支回报差的校准关系；
- 使用/屏蔽分支的首次动作、观测、回应码和奖励差异位置；
- 责任度每槽有效质量，确认目标修订没有重新造成槽退化；
- `posterior_use` 相对 `prior_only` 和 `reference_only` 的匹配回报差。

在回应屏蔽的实际执行动作分箱仍为零效应时，不应生成十单元正式任务。

## 10. 限制与仍未回答的问题

- 当前只有一个 seed-100 checkpoint，不能判断潜在槽分化和责任度集中的跨训练重复性。
- 完整控制路径追踪只有 32 个回合，足以定位接线和算子失配，不足以估计任务效应大小。
- 训练伙伴是否在匹配公共上下文中具有不同动作价值签名的只读 oracle 审计尚未实现。
- 500 回合回应屏蔽对照只保存最终回报，没有保存动作和信念分支差异；本次额外追踪弥补了诊断，
  但原始正式开发行仍缺少这些字段。
- 8 个活动价值商来自当前严格等价规则；它证明槽未被合并，不证明每个槽对应稳定、可复现的
  控制类型。
- 本报告没有评价 Test Time Wide、十单元跨策略矩阵或 Hanabi，因为 V4.1 尚未进入这些阶段。

进一步需要回答的核心问题只有一个：在与真实 KL 执行一致后，回应信息是否仍有正的可执行
价值。这个问题应由下一次同预算开发复跑回答，而不是由当前结果外推。
