## 一、结论先行：病不在"门多"，在"三件事"

对抗性复核（默认保护载重门）的结果是诚实的：**大多数深层门确实载重**，每一道都对得上上面某一次真实、昂贵、有记录的失败，砍掉就等于把那次失败重新放进来。所以"大刀阔斧"**不等于**削科学护栏。

真正让你"每次都得先建门才能动手"的，是三类**与任何真实失败都对不上**、或**纯属重复**的负担：

1. **两处人工签字礼仪**——启动前的人工签字（§3 的 `AUTO_PROCEED=false` + 每次启动 human checkpoint）和实验中途签字（签B / 签②）。对抗复核结论原话："启动前签字对不上任何真实失败""中途签字是'启动很重'的最大单一来源"。它们捆绑的每一项实质检查，都在别处有独立的门保着，签字本身只增加一个来回延迟。**保留的人工判断只有一个：最终读数裁决（签C / 签③）**——那一个真的抓到过 INC-4 的缺陷，留。

2. **同一条规则被抄在 3–5 个文件里的"重复税"**——`data-sufficiency-floor` 同时写在 OPERATING §6、PREREG、METHOD_LOCK；P1/P4/P5/S17/S20 同时写在 DASHBOARD、FIDELITY、LEDGER、METHOD_LOCK。全仓 **124 处门条目**去重后其实只有 **约 20–25 条唯一规则**。每条给一个唯一归属 + 别处只放指针。

3. **"启动前必须绿"被误当成门，其实该是"读数前审计"**——FIDELITY 的 I1–I9 是静态的方法身份检查（几秒钟一条命令跑完），它们不该拦"能不能开跑"，只该在**读结论前 / 改动方法代码后**为绿。真正必须拦启动的只有"事后无法补救"那几项：preflight 布局合法性、数据预算、去 oracle 证据通道、盲测划分不污染。

再加两类清理：**已关闭/已失效却仍列为在架的门**（约 13 条 ARCHIVE），和**结构上是重言、条件早已满足的门**（如"有结果文件才能 result-to-claim"、"收到评审才能 rebuttal"）。

计数：**124 条门条目 → 保留 75、降级 24、归档 13、合并 12**。去重后唯一载重规则约 20–25 条。

## 三、保留（载重护栏，一律不动）

每一条都对得上一次真实、昂贵、有记录的失败，砍掉即重开该失败：

- **数据充分性**：≥2000 局/40k transitions 下限、从产物回读有效预算、smoke 只作 Type-A 不可引用、诊断前先问预算——全部对应 INC-1（一个月代价）。
- **去 oracle 证据**：P1（行为推断伙伴选项、不注入真标签）、P5（reward/探索/replay/eval 不喂真 terminal_policy）——对应 INC-4/INC-3，且 P5 在 v3/v4 曾**重新扩张**（有记录的复发）。
- **信念机制**：P4（信念隐状态跨决策持续）——对应把机制变成"失忆模型"的真缺陷。
- **CE 支持哨兵**：P3（CE=0 是支持不足哨兵，非测得零）——它localize 了 S27。
- **eval 完整性**：S17（一个 flag 不得关掉全部完整性门）、S20（headline 归我方所有、记录分角色）、S23（held-out 划分不污染）、NEW-2（检查点先判定后存盘）。
- **preflight 硬门**：对应 S27 污染 12000 行 replay；事后无法补救，必须拦启动。
- **cross-model 代码评审（不同模型族）**：对应 INC-4 真缺陷（本方模型自审抓不到）。
- **盲测完整性**：从参数空间构造、封存后不再动、单看规则 + grep 审计——让 INC-2 的负结论可信而非被反复试出来。
- **r2.1 伙伴差异化证书**：对应 INC-3——挡"退化到公共状态、迁移仍成立"的基底进入正式 claim。
- **两个真正的人工判断点**：启动授权（就是"不本地执行"边界 + 用户真实同意）、最终读数裁决（签C/签③，抓到过 INC-4）。
- **prereg 冻结决策表 + 分支表**：对应 INC-4（挡事后叙事套噪声）。
- **ITT 全臂全 seed 入表不排除**、**一次一变量**、**不解决掉现象声明**、**读数产物自检**、**自动完整性硬门**、**不得在合成/自造伙伴上报 headline**、**跨门须凭记录证据非推断**、**下游工作流须凭 Type-B 签收解锁**——均对应有记录的真实失败或活的陷阱，零启动成本。

## 四、装上"退休阀门"（防止棘轮重新长回来）

病根是"只进不出"：每踩一次坑就加一道永久门，从无移除机制。补丁（落入 OPERATING_CONSTRAINTS §7）：

1. **加门须报两样**：它防的那一次**具体真实失败**，和它的**退休条件**。两样都没有，就不作"拦启动"的门，最多作事后审计。
2. **默认高度=拦 claim，不拦启动**：只有"事后无法侦测或补救"的失败才允许拦启动（preflight、数据预算、去 oracle 证据、盲测划分污染）；其余一律事后/读数前审计。
3. **一条规则一个归属**：新规则只写一处，别处放指针，不得三处重述。
4. **定期清扫**：对应失败已关闭、或条件已满足的门，归档。
