## 0. 为什么是完整 Hanabi(且不许简化)

三条判据(上一轮定的,缺一条就重蹈 OvercookedV2 覆辙),Hanabi **同时**满足,简化版会破坏其中之一:

1. **反应无法替代(现象真存在)。** Hanabi 的伙伴约定是**结构性隐藏**的:两个处在**完全相同牌面**的伙伴可以
   持不同约定,只能从"提示 → 后果"的历史里推断。牌面本身不决定它——这正是 OvercookedV2 给不了的、非空间的
   隐藏轴。**简化牌堆/减手牌会削弱约定空间,把它推回可反应。**
2. **held-out 伙伴不由我们设计。** 独立自博弈 agent、规则约定 bot、(可选)人类约定代理——他们的约定是**他们
   的**,不是我们捏出来"恰好可推断"的。这堵死了 toy 的镜像病根。
3. **可证伪 + 可调难度。** cross-play(与独立伙伴配对的回报)是标准、可判负的度量;约定分歧程度天然给出一条难度轴。

**一句话:Hanabi 是第一个能把"反应"和"预判"干净分开、且伙伴不归我们管的基底。** 这就是不许简化的原因——
任何简化都是在把我们控制不了的硬度,换成我们控制得了的方便。

## 1. Hanabi 天然把"反应 / 预判"分成两层信念(这正是我们要测的)

Hanabi 里对一个"信念型"agent 有价值的隐藏量恰好两块:

- **手牌信念(react 侧,可观测驱动):** 我看不见自己的牌,伙伴的**提示**告诉我。提示是**公开可观测**的 →
  这一层是纯反应,信念从当下线索更新。
- **约定信念(anticipate 侧,隐藏驱动):** 这个伙伴到底怎么编码/解读提示?只能从**提示的后果**跨回合累积推断,
  且要在当前这张牌的约定被揭示**之前**就用上它(要不要把一个提示当"可打")。**这一层从当前牌面读不出**。

→ Hanabi **按构造**把 OvercookedV2 混在一起、我们分不开的两件事分开了:手牌信念 = 反应,约定信念 = 预判。
我们的核心主张("value-only 信念能预判隐藏伙伴倾向、且泛化到 held-out")第一次有了能被**干净证伪**的地方。

## 2. 真正的坎:方法在 Hanabi 里怎么实例化(需要 METHOD_LOCK 裁决)

方法之所以"贴合"OvercookedV2,是因为它围着 OvercookedV2 的结构长成:空间 option、终端机会、CE 支持图。
**Hanabi 没有这些。** 所以必须先在纸上答两问,而且很可能**要动 METHOD_LOCK**(方法层改动,按项目规则须走修订门):

| 抽象 | OvercookedV2 里 | Hanabi 里(提议) | 是否动 method-lock |
|---|---|---|---|
| 价值充分因子(factor) | 角色 / 终端倾向等 | **{每张牌的可打性/身份信念} ∪ {伙伴约定信念}** —— 约定因子就是承载 ZSC 主张的那个 | 是:新增"约定因子"语义 + 其证据路由 |
| option(时序动作抽象) | 空间 option | Hanabi 动作是原子的(给某人提示 / 出第 i 张 / 弃第 i 张)→ **option 层大概率去掉** | 是:去掉 option 机制 |
| 因子局部 Q + 单 TD | 不变 | 不变(仍是单 TD、纯价值,无辅助损失) | 否 |

**这是给用户/项目负责人的第一决策,不是我能自签的:** 上面的因子重定义 + 去 option,构成一次
**METHOD_LOCK 修订**(方法身份变化)。要么走正式修订预注册,要么否掉这个映射、给出别的因子定义。
**在这一票落定前,下面都是待定设计,不进入执行。**

## 3. 可证伪 + 伙伴不由我们设计(把上一轮的判据落到 Hanabi)

- **训练伙伴分布:** 独立自博弈池(不同种子/结构)+ 规则约定 bot(固定但彼此不同的解读规则)。
- **held-out(blind)伙伴:** 约定**机制类与训练不相交**(不同 finesse 层级 / 不同 save 优先级 / 独立第三方 agent),
  见到方法行为**之前先密封**(沿用 sec18.14 密封 + 单看程序)。**关键:held-out 约定不是我们为"可推断"而造的。**
- **主度量(可判负):** 与 held-out 伙伴的 **cross-play 回报**;外加因果用信念电池——**约定信念交换**(把推断出的
  约定信念换成另一类型,出牌是否随之改变)+ 历史遮蔽。
- **证书在约定轴上重表达(复用 C-1..C-5 机制):** C-4 = 约定"从历史可辨、从当前牌面不可辨";
  C-5 = 知道约定能改变最优出牌 / 打赢一个"反应式:等着看它怎么提示"的 ego。**这一轮证书若判负,也是干净、
  可发表的负结果——但这次是方法被证伪,不是基底 reactive-sufficient。**

## 5. 序、门、成本、风险

| 阶段 | 内容 | 门 |
|---|---|---|
| H0 | **METHOD_LOCK 裁决**(§2 的因子/option 映射) | 用户 Type-B;否则本计划不动 |
| H1 | Hanabi 适配 + 方法实例化 + Type-A 接线检查 | 跑通、单元测试、因子实例化 |
| H2 | 训练/held-out 伙伴池 + 约定密封 + 证书在约定轴落地 | 覆盖 + 密封 + 证书机制绿 |
| H3 | 充分性重标定(Hanabi 局数下限,从产物回读) | plateau 记录 |
| H4 | 涌现测试预注册(cross-play + 约定信念因果电池 + 证书)→ 跑 → 跨模型评审 + 人工 Type-B | 判负也是证据 |

- **成本:** 方法移植是长杆(数周);算力上千 GPU-h 量级(survey 估 ~900–1500)。JaxMARL 已有 Hanabi env,**环境不是长杆**。
- **风险 1(最深):** §2 的因子映射可能立不住 —— 若"约定因子"在方法框架里无法定义,问题就在方法本身,H0 就该停。
- **风险 2:** 预判主张**仍可能真的失败**(信念不泛化、猜错、不如反应)——但这次是**可证伪、伙伴不归我们管**的失败,
  这正是要的:一个能说"方法不行"的测试。
- **风险 3:** cross-play 里"约定不兼容"与"信念没预判"要能分开——用约定信念交换(因果)与独立 vs 反应 ego 对照区分。
