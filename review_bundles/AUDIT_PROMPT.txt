## Audit Checklist

### A. Ground Truth Provenance
For each evaluation script:
1. Where does "ground truth" / "reference" / "target" come from?
2. Is it loaded from the DATASET/ENV, or generated/derived from MODEL OUTPUTS?
3. If derived: is it explicitly labeled as proxy evaluation?
4. Are official eval scripts used when available for this benchmark?
FAIL if: GT/reference is derived from model outputs without explicit proxy labeling. (Pay attention to: within-run relative return vs oracle/reference-gap closure labeling; random_policy baseline provenance.)

### B. Score Normalization
1. Is any metric divided by max/min/mean of the model's OWN output?
2. Are raw scores reported alongside any normalized scores?
3. Are any scores suspiciously close to 1.0 / 100%? (e.g. self-referential raw_value 1.0)
FAIL if: Normalization denominator comes from prediction statistics.

### C. Result File Existence
For each claim in the plan/dashboard/proposal:
1. Does the referenced result file actually exist?
2. Does the claimed metric key exist in that file?
3. Does the claimed NUMBER match the file?
4. Is the tracker status DONE (not TODO/IN_PROGRESS)?
FAIL if: claimed results reference nonexistent files or mismatched numbers. (Check the matrix config.full_diagnostics vs eval_results.json for provenance conflicts.)

### D. Dead Code Detection
For each metric function defined: is it actually CALLED, and does its output appear in a result file? (e.g. factor-deletion q_proxy vs rollout; Δ_info/MI.) WARN if defined but never called.

### E. Scope Assessment
1. How many scenes/layouts/configs/seeds were actually tested?
2. Does the proposal/dashboard use "comprehensive/extensive/robust/formal" language?
3. Is the actual scope sufficient for those claims?
WARN if scope language exceeds evidence.

### F. Evaluation Type Classification
Classify each evaluation: real_gt | synthetic_proxy | self_supervised_proxy | simulation_only | human_eval.

## Output Format
For each check (A-F): Status PASS|WARN|FAIL, Evidence (exact file:line), Details.
Then: Overall verdict PASS|WARN|FAIL.
Be thorough. Read every eval script line by line.
